# 方案:Markdown 代码块一键执行(ADR-023)

> 状态:已实现(v0.3.3 开发中,记入 `[Unreleased]`)
> 日期:2026-07-31
> 关联:软件定义书 ADR-023;CHANGELOG `[Unreleased]`

## 1. 背景与目标

Marina 的 AI agent 工作流里,agent 经常在 Markdown 报告 / 计划里输出可执行的 shell
命令(`npm test` / `git status` / 一段 PowerShell)。用户希望像 JetBrains IDE 那样,
代码块旁边有一个「运行」按钮,点了直接跑,而不是手动复制 → 切终端 → 粘贴 → 回车。

Marina 的 Markdown 面板(`FilePanel` → `MarkdownViewer`)是现成的展示位,已有
`sessionId` 绑定,是天然的落点。

## 2. 关键决策

### 2.1 执行模型:直接 spawn,不经 PTY

**采用** `child_process.spawn` 启动对应 shell 一次性跑完整 code。

明确**不做**:
- 不调 `SessionManager.sendInput()` 写当前 PTY —— 当前终端可能是 Claude Code / Codex /
  vim,把 shell 命令当输入喂给它们语义错误(会变成 prompt / 进 vim)。
- 不创建新 Marina Shell session 后再模拟输入 —— 多一层状态,且污染 session 列表。

这样当前终端前台运行什么程序都不受影响;命令在独立的系统进程里跑。

### 2.2 工作目录:服务端 session.currentCwd

cwd 由 `sourceSessionId` 的**服务端** `currentCwd` 决定。renderer 不传 cwd,也不被信任;
main/daemon 从 `SessionManager` 真值读取。与「路径中心」哲学一致 —— 命令在用户当前
聚焦的路径下跑。

### 2.3 本地 / 远程一致

IPC 走 backend-data 域,preload 自动路由:本地窗口发本地 main,远程窗口发远程 daemon。
**SSH 终端拒绝**:其 `currentCwd` 在第三台机器,本进程无法在那 spawn(与 file-tree /
git-service 的 SSH 拒绝策略对称,不引入远程协议)。

### 2.4 无确认弹窗

产品决策明确移除风险分级 / 确认框 / 信任目录 / 命令扫描 / 行数限制等交互约束 ——
点击即跑,失败只弹 toast。唯一触发方式是用户手动点击「运行」,打开 / 滚动 / 刷新
Markdown 绝不自动执行。

### 2.5 运行结果是 L1 工作态,不落磁盘

代码块运行状态 / 流式输出 / 退出码与文档浏览位置同属“切换后丢失会烦、重启可丢”的
L1 工作态。renderer 用组件外有界 cache 保存;切 terminal、文件面板或组件重挂后恢复,
运行中的独立进程不因 UI 卸载而停止。输出可能含路径、token 或命令结果,禁止写入
localStorage / main 日志 / 持久化文件。用户通过「清除」按钮显式重置已结束结果。

## 3. 语言归一化

`src/shared/markdown-command.ts` 是语言别名表的唯一真相源:

| Markdown 标签 | 归一化 | spawn argv |
|---|---|---|
| `bash` / `sh` / `shell` / `zsh` / `fish` / `ksh` / `dash` | `bash` / `sh` | `bash -c <code>`(Win 上 `bash`=Git Bash;不读登录 profile) |
| `powershell` / `powershell.exe` / `posh` / `ps1` | `powershell` | `powershell.exe -NoProfile -Command <code>` |
| `pwsh` / `pwsh.exe` | `pwsh` | `pwsh.exe -NoProfile -Command <code>` |
| `cmd` / `cmd.exe` / `bat` / `batch` / `dos` | `cmd` | `cmd.exe /d /s /c <code>` |

未列出的语言(`python` / `json` / ...)→ 不显示「运行」,只有「复制」。

## 4. IPC 协议

| channel | 方向 | payload |
|---|---|---|
| `cmd:system:run-code-block` | renderer→main | `{ sourceSessionId, language, code }` → `{ runId }` |
| `cmd:system:stop-code-block` | renderer→main | `{ runId }` |
| `evt:system:code-block-output` | main→renderer(定向) | `{ runId, stream, data }` |
| `evt:system:code-block-exited` | main→renderer(定向) | `{ runId, exitCode, signal }` |

事件按 runId 对应的发起 client 定向发送(本地窗口 = windowId,远程 = WS clientId),
与 session output 的定向策略一致。stdout/stderr 在 main 端按 64KB / 100ms 聚合切块,
避免逐字符广播砸 IPC。

## 5. 生命周期与边界

- 发起窗口关闭 → `CodeBlockRunner.removeClient` 杀掉它启动的全部运行(避免向已销毁的
  webContents 推事件 + 回收子进程)。
- 源 Session 真正销毁 → `CodeBlockRunner.removeSession` 停止该 session 启动的运行,
  close 后仍向存活窗口发 exited 收口 cache;普通 terminal 切换不销毁 Session,不命中。
- 组件卸载(切 terminal / 文件 / 面板)只退订该组件的 store listener,**不发 stop**;
  `code-block-run-cache.ts` 的窗口级事件桥继续接收 output / exited,切回后恢复。
- cache identity = sessionId + 文档路径 + Markdown 源位置 + 代码摘要;同文档重复代码块
  不串结果,换 session/cwd 不共享。缓存最多 128 条,单条输出最多 2Mi 字符,只淘汰
  非 running 条目;不写 localStorage / 磁盘。
- 用户在输出区 footer 右侧点击「清除」,删除已结束结果并回到 idle;退出状态留在
  footer 左侧。运行中不允许清除(必须先停止/等待退出),防止 UI 丢掉仍存活任务的 runId。
- 同时存活运行数硬上限 64,溢出 FIFO 强杀最旧。
- 代码原文上限 256KB(防 AI / 误粘巨型内容撑爆命令行参数缓冲)。
- 命令正文 / stdout 不写入日志或性能报告(附录 H 隐私红线);日志只记 runId / 语言 /
  exitCode 等数值与固定标签。

## 6. 不做(本期内)

- 命令历史 / 重跑记录。
- 信任目录 / 永久授权 / 风险分级。
- 步骤编排 / 多代码块组合。
- 内联输出投到主终端(刻意分离:代码块输出留在代码块下方,不污染终端 scrollback)。

## 7. 迭代修复(2026-08-01)

首轮交付后实测反馈的一批修复:

- **shell 解析走 detectShells 绝对路径,不靠 PATH。** Electron main 的 PATH 经常没有
  `pwsh.exe` / Git Bash(用户装了但不在 PATH),直接 spawn 报 ENOENT(close 时
  exitCode=-4058)。改用应用自身 detectShells 结果(与 SessionManager 同源缓存)的
  绝对路径;getShells 失败回退 PATH 名不阻塞。spawn 后异步 ENOENT 也给友好提示
  而非裸的 -4058。
- **cmd 输出 GBK 自动检测解码。** cmd.exe 按系统 ANSI 代码页(中文 Windows = GBK)
  输出,`chcp 65001` 对管道输出无效(实测中文变问号)。新增
  `DetectingOutputDecoder`:纯 ASCII 直接输出,首段非 ASCII 用 fatal UTF-8 判定,
  失败则按 GBK;TextDecoder(stream) 处理跨 chunk 多字节切分。PowerShell/pwsh
  仍用命令前缀强制 UTF-8。
- **pwsh 回退 powershell。** 未装 PowerShell 7 的机器上 pwsh 语言回退到 Windows
  PowerShell 5.1(powershell.exe 在 Windows 必装),SHELL_ID_PREFERENCE 改为
  `['pwsh', 'powershell']`。UTF-8 前缀 5.1/7 通用。
- **运行选中片段。** 在代码块内选中文本后,“运行”按钮变“运行选中”,只跑选中部分。
  selectionchange 只在“有无选区”翻转时重渲染;选中文本存 ref 避开“点按钮清选区”竞态。
- **透明外壳样式契约。** 代码块外壳 / toolbar / output 全透明,hover/选中反馈一律用
  `color-mix(in srgb, currentColor N%, transparent)`(不用主题 bg token —— 那些按应用
  主背景调色,在透明外壳上会出黑块)。`src/renderer/styles/global-css.test.ts`
  守护这条契约:`npm test` 自动拦截代码块规则里出现 `var(--color-bg-*)` 的回归。
