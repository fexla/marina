# 方案:Markdown 能力默认全源复用(2026-09-10)

> 状态:已实现(ADR-036)。开发者裁决原话:"这就是失误,markdown 的功能应该
> 默认就是复用的。" 本文记录病灶、裁决的落地方式与安全面论证。

## 1. 病灶:能力门控按来源手工分叉

ADR-035 落地后暴露的不对称:命令面板输出里 `[x](./a.md)` 点不动,但
`[x](<marina:show ./a.md>)` 能打开同一个文件。根因是 fileContext(真实文件
路径)长期充当**能力门控** —— 本地链接、本地图片、gallery、标题目录全部
`filePath !== undefined` 才开,命令面板输出(无文档路径)一律降级。后果:

- 每个新路径能力都要人工决定"命令输出给不给",漏接即不对称(本次裁决的
  直接触发点);
- 插件数组双分支(文件来源多挂 heading-sections),新插件要记得改两处;
- 门控散落在 MdLink/MdImage/gallery 分发/rail effect 五处以上。

原设计的安全初衷是对的 —— **渲染层不许猜 cwd**(ADR-018 时代的决策),
但 ADR-035 的 marina:show 已经证明"main 端按真值基准解析"这条路安全且
体验正确,旧的"无文档路径 = 无路径能力"等式不再成立。

## 2. 裁决落地:能力默认同享,差异只在解析基准

| 维度 | 文件来源(「已打开」面板) | 命令来源(命令面板输出) |
|---|---|---|
| 插件管线(GFM/frontmatter/章节化/目录轨/裸路径链接) | ✅ | ✅(单一数组,不分叉) |
| 本地文件链接 | ✅ md 目录基准 + 成员校验 | ✅ **运行时 cwd** 基准 |
| 本地图片 / gallery | ✅ 同上 | ✅ 同上 |
| marina:show 相对路径 | ✅ md 目录 | ✅ 运行时 cwd(优先)/ 当前 cwd(回退) |
| 标题目录 / 章节折叠 / Ctrl+F | ✅ | ✅ |

### 2.1 运行时 cwd(runCwd)而非点击时 cwd

命令在 session cwd 下执行,输出里的相对路径语义锚定**运行那一刻**的 cwd。
终端随后 cd 走,旧输出的相对路径不能跟着漂移(指错文件或 404)。因此:

- `CommandEntry.runCwd`:CommandPanelService.spawnRun 时记录
  `lookup.get(sessionId).currentCwd`(与 CodeBlockRunner 的 spawn 基准同源);
  重跑刷新即更新;持久化(与 command 字符串同隐私级别);可选字段兼容旧快照。
- `CommandPanelService.getRunCwd(sessionId, commandKey)`:只读查询,ipc 层用。
- 旧快照无 runCwd / 极端无 commandKey → 回退 session 当前 cwd(ADR-035
  原语义),不比之前更差。
- SSH session:currentCwd 是远端路径,本地 fs 解析失败 → toast(与 CLI
  show 同语义,不静默)。

### 2.2 安全面论证(为什么这不是放松)

- **文件来源的成员校验原样保留**(mdPath ∈ 该 session 已打开列表,
  resolvePanelPathBase 的 mdPath 分支)。
- **命令来源的基准是 main 自己记录的真值**(runCwd),renderer 只传
  commandKey 标识 —— 想伪造基准无从下手。
- 权限面等价性:命令来源"相对 cwd 打开/读文件"的能力,与 UI「打开文件」
  按钮的 FILE_PANEL_OPEN(owner 校验 + session cwd 基准 + 任意绝对路径)
  完全等价;只读面板不外发内容。不引入新边界。
- 渲染层依旧**永不猜路径**:所有解析(resolve/成员校验/stat)都在 main。

### 2.3 实现接缝

- **protocol**:CommandEntry.runCwd;OPEN_PATH/READ_IMAGE/GALLERY_*/MARINA_LINK
  各 payload 增 `commandKey?`,mdPath 改可选(两者恰好给其一)。
- **FilePanelService**:私有 `resolvePanelPathBase`(mdPath XOR baseDir,含
  成员校验/绝对路径校验);`openFileFromBase` 新方法;readImageAsset/
  resolveGalleryImage/openGalleryImage 签名放宽(mdPath?: string, baseDir?)。
- **ipc**:handler 内 `commandBaseDir()` = getRunCwd ?? session 当前 cwd,
  五个通道统一走它。
- **渲染层**:新增 `md-src-base.ts`(MdSrcBase + mdSrcBasePayload 构造器,
  收口"恰好给其一"的展开,三处组件不再各写一份);MarkdownDocument 的
  srcBase **必须 useMemo**(对象身份进 MdImage 解析 effect 依赖,不 memo
  会每次父渲染重发图片 IPC);插件数组单一化;滚动容器选择器
  `.file-panel-body, .command-panel-body` 双认(目录轨激活/折叠滚动补偿)。

## 3. 不做的事

- 不给命令输出开 `show --heading` 式的一次性导航意图(headingNavigation
  仍文件 adapter 专属 —— 命令输出的标题导航用目录轨/锚点已覆盖)。
- 不缓存 runCwd 历史(只需最近一次;刷新即覆盖)。
- 不在 SSH session 上做远端路径解析(与 CLI show/git 面板同策略,拒绝)。

## 4. 测试

- command-panel-service:runCwd 记录/重跑更新/未知查询返 null。
- file-panel-service:openFileFromBase(相对/绝对覆盖/heading 透传/非绝对
  拒绝/NotFound)、readImageAsset 与 gallery 的 baseDir 分支、双基准同给报错。
- marina-link-dispatch:commandKey→openFileFromBase、runCwd 缺失回退 openFile、
  mdPath 优先。
