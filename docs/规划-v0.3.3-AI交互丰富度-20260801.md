## 0. 版本主题

**核心：丰富 AI 调用 Marina 的能力丰富度。** 上一版本（ADR-023）落地了「可执行代码块」
（bash/powershell/cmd 一键运行），AI 已经能把命令塞进 Markdown 让用户一键跑。0.3.3
继续在这条线上扩展：

- AI 能往文档里放**图片画廊**（不只是命令），省空间、可看大图；
- AI 放的**文件链接 / diff** 能一键在面板内打开查看；
- AI 能**绑定并复用工作空间**（含文件面板状态），跨 Marina 重启延续上下文；
- 顺带把**侧栏**重度使用后暴露的乱（无层级、不能拖、条目看不清）一并整理。

一句话：**让 AI 产出的东西更立体（图/文件/工作空间），让用户操作它们更顺手。**

> 注：本批所有「打开文件」均指**在面板里查看原文件**（只读）。Marina 面板不是编辑器，
> 不涉及编辑能力。

## 1. Feature 概览与依赖

| ID | Feature | 主题 | 现状基础 | 难度 | 是否阻塞 |
|---|---|---|---|---|---|
| A | 图片表代码块（Gallery 幻灯片） | AI 交互 | 复用 MarkdownCodeBlock 分发 + readImageAsset | 中 | 否 |
| B | Markdown 文件链接 → 面板内打开（只读查看） | AI 交互 | MdLink 现无相对路径处理 | 中 | 否 |
| C | Diff 页面「打开文件」入口 | AI 交互 | DiffViewer 已知文件路径；GIT_OPEN_FILE 已存在 | 低 | 否 |
| D | AI 接口绑定/复用工作空间（含文件状态持久化） | AI 交互 | workspace 纯临时、无枚举/绑定 API、无状态快照 | **高** | 否（但设计空间最大） |
| E | 侧栏整理（层级 + 拖拽 + 条目 UI） | UI | PathNode 平铺、无 dnd、圆点非边框 | 中-高 | E1 数据模型改动需早定 |

**依赖关系**：
- A、B、C 三者都落在 file-panel 的 Markdown/查看器层，相互独立，可并行。
- D 是独立的新子系统（CLI + main + 持久化 schema + 文件面板状态快照），与 A/B/C 无耦合。
- E1（路径层级）是**数据模型级改动**，会动 `PathNode` / `PathTree` / `bookmarks.json`，
  建议最早评审定稿，否则 E2/E3 的实现会被它牵动。
- E2（拖拽）依赖选定的 dnd 方案，E3（条目 UI）独立可先做。

**建议实现顺序**：E3（条目 UI，独立、立竿见影）→ C（最小）→ B → A → E1+E2
（数据模型 + dnd，一起做）→ D（最大、最后）。

## Feature A：图片表代码块（Gallery / 图片幻灯片）

### A.1 目标（用户意图）

- 一种**特殊代码块**，语言标签表示「图片表」；块内**每行一个图片链接**（本地路径或 URL）。
- 渲染成**幻灯片**：一次只显示一张，左右切换，不把所有图平铺出来（省空间）。
- 点图片 → 打开一个**独立窗口**看大图、可缩放。用户倾向：直接调 **Windows 系统原生图片查看器**，不在 Electron 里自造图片浏览器。

### A.2 现状基线（已探明）

- `MarkdownViewer.tsx:78-96` 的 `pre` 组件已按语言分发：shell 语言（bash/powershell/cmd）
  → `<MarkdownCodeBlock>` 可运行外壳；其他语言 → 普通 `<pre><code>`。**新增一种「伪语言」走第三条分支即可。**
- 图片读取已具备：`MarkdownViewer.tsx` 的 `MdImage` + `normalizeMdImageSources`
  （行 116-140）+ `cmd:file-panel:read-image`（`FILE_PANEL_READ_IMAGE`）→ main
  `readImageAsset`（file-panel-service.ts）把相对 md 目录的本地图读成 dataUrl。
- 打开本地路径用系统默认应用：`SYSTEM_OPEN_PATH`（`cmd:system:open-path`，ipc.ts:1325，
  走 `shell.openPath`）**通道已存在**，面板 tab 右键已在用（FilePanel.tsx:169）。
- `ImageViewer.tsx` 现有单图 dataUrl 展示能力（无缩放/轮播）。
- **CSP 约束**：prod `img-src 'self' data:` 会挡**网络图片**（http URL 的 `<img>`）；本地图
  走 dataUrl 不受影响。网络图需下载落盘绕开。
- 协议侧：`CodeBlockLanguage`（protocol.ts:1158-1164）是有限枚举，新增语言标签要扩展。

### A.3 设计要点

1. **语言标签**：建议 ` ```gallery `（语义直观：画廊）。块体每行一个图片链接，纯路径/URL，
   不支持 markdown 行内语法（保持简单，和代码块语义一致）。
2. **渲染组件**：新增 `GalleryViewer.tsx`（与 `MarkdownCodeBlock.tsx` 并列），由
   `MarkdownViewer` 的 `pre` 分发器在识别到 `gallery` 语言时挂载。
3. **幻灯片交互**（省空间优先）：
   - 一次显示一张主图，高度自适应但有上限（避免单图撑爆面板）。
   - 左右箭头按钮切换 + 顶部指示器 `3 / 8`。
   - 支持键盘 ←/→（仅当 gallery 聚焦/hover 时拦截，避免和终端、Ctrl+F 冲突）。
   - **底部缩略图条**（小预览，点击跳转）——**v1 要做 [已裁决]**。
4. **图片来源解析 + 懒加载**：
   - 本地相对路径：复用 `readImageAsset` 逻辑（相对 md 文件目录解析 + dataUrl）。
   - 绝对路径 / `file://`：校验后读成 dataUrl（复用现有通道）。
   - 网络 URL（http/https）：**v1 纳入 [已裁决]**。先下载到
     `MARINA_WORKSPACE/__marina_gallery__/` 临时文件，再当本地图处理（统一走 dataUrl /
     openPath）。既绕开 CSP，又让「点开用系统查看器」对网络图也生效。
   - **懒加载**：幻灯片主图 + 缩略图条都**不一次性加载全部**，只加载当前可见张 ±1；切到位时
     再拉。网络图尤其依赖懒加载避免阻塞。
5. **远程访问（SSH session）**：远程终端的 workspace 在本地 daemon，但 gallery 里引用的
   **本地路径**（如 `./screenshot.png`）指向**远端机器**的文件，本进程读不到。策略与
   file-tree / git-service 的 SSH 拒绝对称：远端本地图 → 拒绝加载 + 占位提示；网络图（URL）
   不受影响（daemon 可直接拉）。懒加载让「不可达的图」不会拖垮整个画廊。
6. **点图打开大图**：点击主图 → 对应**本地文件**（已落盘的）走 `SYSTEM_OPEN_PATH`
   （`shell.openPath`）→ Windows 系统图片查看器。**零自造成本**，缩放/全屏/翻页都交给系统。

### A.4 开放问题（实现时定 / 已裁决项见 §4）

- **语言标签定名**：**[已裁决] `gallery`**。
- **画廊默认高度 / 长宽比策略**：固定高度裁剪？按首图比例？需定一个不撑爆面板的规则。
- **缩略图条尺寸/数量**：宽度、最多显示几个、溢出是否滚动？待实现时定。
- **网络图下载策略**：超时多久、失败如何提示（占位 + 重试按钮）、下载的临时文件何时清理
  （随 session 销毁 / 随 workspace 回收）。

### A.5 改动面

- 新增：`src/renderer/components/file-panel/GalleryViewer.tsx` + 样式（global.css）。
- 改：`MarkdownViewer.tsx`（pre 分发器加 gallery 分支）、`src/shared/markdown-command.ts`
  或新增 gallery 语言识别、`src/shared/protocol.ts`（如扩展枚举）。
- 改：`file-panel-service.ts`（网络图下载落盘的路由/函数）。
- 测试：gallery 渲染、切换、懒加载、路径解析、网络图下载失败（单元）；点图 openPath（mock）。

## Feature B：Markdown 文件链接 → 面板内打开（只读查看）

### B.1 目标（用户意图）

- 文档里的**文件链接**，点一下直接在 Marina 文件面板里打开**查看原文件**（只读，不编辑）。

### B.2 现状基线（已探明）

- `MarkdownViewer.tsx:105-114` 的 `MdLink` 现状：
  - http/https/mailto → `preventDefault` → `cmd:system:open-external`（系统浏览器）。
  - 页内锚点 `#xxx` → 不拦截，默认滚动。
  - **相对路径 / `file://` 链接 → 无任何处理**，被当外链走 open-external，而 main 对
    `file://` 与非 http(s) 一律拒绝（见 protocol.ts 注释与 SYSTEM_OPEN_EXTERNAL handler）→ **点击实际无效**（仅 console warn）。
- 打开文件进面板的现成能力：
  - `FILE_PANEL_SHOW`（`cmd:file-panel:show`）切 active（点已有 tab）。
  - CLI `show` 走的 `POST /open-file` → `FilePanelService.openFile()` 状态机（加/更新 tab、
    切 active、ensureWatcher）——**这是「打开任意路径进面板」的完整入口**，可复用。
  - `GIT_RESOLVE_PATH`（`cmd:git:resolve-path`）能相对工作区解析路径。

### B.3 设计要点

1. **链接识别规则 [已裁决 #4]**：
   - **默认 = 本地文件**：链接目标**不是**完整 `http(s)://` / `mailto:` URL 的，一律当本地文件
     路径 → 进面板**只读查看**（相对 md 文件目录解析）。
   - **外链 = 完整 URL 格式**：以 `http://` / `https://` / `mailto:` 开头的才识别为外链 → 走
     `open-external`（系统浏览器）。这就是「定一个格式识别外链」——格式即**完整 scheme URL**。
   - 页内锚点 `#xxx` → 不拦截，默认滚动。
   - **此约定要写进 show-in-marina 的 SKILL**（见 B.5），让 AI 知道：本地文件直接写路径、
     网页写完整 `https://` URL。
2. 路径解析基准：**md 文件所在目录**（与 `readImageAsset` 对图片的处理一致，用户心智统一）。
   - 若 md 来自 workspace（show-in-marina 产物），相对它解析；若是用户磁盘 md，相对磁盘目录。
3. 打开方式：复用 `FilePanelService.openFile` 的语义（加 tab + 切 active + ensureWatcher）。
   需要新增/复用一个 **command 通道**（如 `FILE_PANEL_OPEN_PATH`，或直接走现有
   `FILE_PANEL_SHOW` 但它只切 active 不加 tab——需确认能否「不存在则加」）。
   - 倾向：新增轻量 command，参数 `{sessionId, path}`，复用 `openFile` 状态机，
     `requestActivation: true` 自动切到文件面板。
4. 安全校验（防路径穿越 / 任意读）：
   - 复用 `readImageAsset` 的 sessionId 归属校验思路：mdPath 必须是当前 session 已打开列表里的文件。
   - 解析后的路径做 `resolveAndStat`，校验存在性、走与 read-image 相同的权限边界
     （renderer 不可信，main 校验）。

### B.4 其余实现细节

- **链接类型识别**：**[已裁决 #4]** 默认当本地文件；外链用完整 `http(s)://` / `mailto:`
  URL 格式识别（其余一律本地文件）。约定写进 show-in-marina SKILL。
- **打开后是嵌套进当前 session 的面板**（多一个 tab）对吗？倾向是。
- **`.md` 链接**点开后，是当普通文件展示，还是支持「跳转到另一个 md」的导航？v1 当普通文件即可。
- **不存在的路径**点击行为：toast 提示「文件不存在」？倾向是（复用现有 toast）。

### B.5 改动面

- 改：`MarkdownViewer.tsx`（MdLink 分支）、`src/shared/protocol.ts`（可能新增 command）。
- 改/加：`file-panel-service.ts`（暴露「按 path 打开进面板」给 renderer 的 command handler）。
- **改：`src/skills/show-in-marina/SKILL.md`**——写入链接约定（本地文件直接写路径→面板打开；
  网页写完整 `https://` URL→浏览器），让 AI 按约定产出 markdown。
- 测试：相对/绝对路径解析、越界校验、不存在路径提示（单元）。

## Feature C：Diff 页面「打开文件」入口

### C.1 目标（用户意图）

- Diff 视图**左上角**加一个按钮，点击 → 在 Marina 面板里打开这个文件**查看原文**（非 diff，只读）。
- 图标不用铅笔（铅笔语义是「编辑」，面板只读）——换一个语义更准的。

### C.2 现状基线（已探明）

- `DiffViewer.tsx` 渲染 unified diff，**已从 `+++ b/path` 推断出文件路径**并用于语法高亮
  （`buildRows` 行 130-207）。路径信息现成，只是没暴露成「打开」入口。
- **「打开文件」能力已存在**：`GIT_OPEN_FILE`（`cmd:git:open-file`，ipc.ts:1966）→
  `gitService.openFile`（git-service.ts:518）：读**工作区真实内容**（非 diff），进面板；
  **deleted 文件已禁用**（合理）。GitPanel 右键 secondary 操作就在用它（GitPanel.tsx:317-323）。
- DiffViewer 当前**无任何工具栏 / 按钮**（头注明确「不做词级 diff、不做 side-by-side」，
  但没说不能加「打开文件」入口）。
- diff 来源：Git 面板 `openDiff`（GitPanel.tsx:275）→ `cmd:git:open-diff` → 跑 git diff
  写临时文件进 workspace → 进面板。所以 diff 对应的「文件路径」和「repo」信息在打开 diff 时就知道。

### C.3 设计要点

1. DiffViewer 顶部加一个工具栏（左上角），放一个按钮：
   - 图标：换掉铅笔，候选见 §C.4。
   - 点击 → `GIT_OPEN_FILE`（带 repo + 文件路径）→ 进面板显示原文（只读查看）。
2. 路径来源：DiffViewer 从 diff 内容解析的 `+++ b/<path>`，结合打开 diff 时传入的 repo 上下文。
3. 边界：
   - **deleted 文件**：按钮禁用 + tooltip「文件已删除」（gitService.openFile 已会拒，UI 要先灰掉）。
   - **新增文件**（`--- /dev/null`）：打开即看到工作区新文件，正常。
   - **binary 文件**：gitService.openFile 可能返回不可读 → 复用 unknown kind 的占位。

### C.4 其余实现细节

- **图标选择 [已裁决 #5：`file-text`]**：面板只读，铅笔暗示编辑不合适。已查
  `src/renderer/components/icons.tsx`：**`file-text`(FileText) 已注册可直接用**；`eye`/`pencil`
  未注册。定 **`file-text`**（语义中性「这是个文件」、不暗示编辑/外部、零成本），tooltip「打开源文件」。
- **入口位置**：「左上角」是 DiffViewer 内部工具栏，还是面板 tab 栏？倾向 DiffViewer 内左上角（和 diff 内容绑定）。
- **是否同时支持「在文件管理器中显示」**：可选 secondary 按钮，v1 不做。

### C.5 改动面

- 改：diff 打开链路（GitPanel → open-diff）确认把 repo 上下文传到 DiffViewer（若尚未传）。

## Feature D：AI 接口绑定 / 复用工作空间（含文件状态持久化）

### D.1 目标（用户意图）

- 给 AI 一个**接口改变当前工作空间**（运行中切换）。
- 场景：退出 Marina 后再次启动 AI 对话时，**继续用上一次的工作空间**（产物不丢、上下文延续）。
- AI 要能**绑定一个以前的工作空间来复用**。
- **工作空间要记录文件面板状态**（当前版本已有的：打开了哪些文档、文档停在哪个位置等），
  绑定时**自动恢复**之前的文件面板状态。

### D.2 现状基线（已探明，关键事实）

- workspace = **per-session 的受管临时目录**，1:1 绑定 sessionId（`randomUUID()`）。
  - 创建：`session-workspace-manager.ts` `create(sessionId)` → `<root>/<UUID>`。
  - 注入：`session-manager.ts:927-930` 把绝对路径写进子进程 env `MARINA_WORKSPACE`
    （注入在模板 env 之后，模板无法覆盖，有回归测试）。
  - 销毁：session 销毁 → `release()` 标 `closedAt`，目录**不立即删**，保留
    `settings.filePanel.workspaceRetentionDays`（默认 7）天后由 `cleanupExpired()` 删。
  - 存储：`%APPDATA%\Marina\file-panel-workspaces\<UUID>` + `manifest.json`
    （`{version, workspaces: {<sessionId>: {closedAt}}}`）。
- CLI `marina workspace`（marina.ps1 `Invoke-CmdWorkspace` 202-218）：**只读 `$env:MARINA_WORKSPACE`
  打印当前路径**，不生成/不查找/不接受参数。**这是「运行中切换」要改的关键点**（见 D.3）。
- **关键缺口**：
  1. workspace 身份 = sessionId UUID，**无创建时间、无显示名、无标签**（manifest 只存 closedAt）。
  2. **无枚举 API**（manifest 是内部索引，未对外暴露）。
  3. **无 bind/reuse/switch 接口**（CLI / IPC 都没有）。
  4. session **不持久化**（ADR-008），sessionId 每次新建不可复用。
  5. 7 天回收会**删除未保护的旧 workspace**——复用必须让被绑定的 workspace「免回收」。
  6. **文件面板状态不持久化**：当前「打开了哪些文档、滚动位置」是 renderer 内存（store.tsx
     的 `filePanels` Map），session 销毁即丢，没有任何快照进 workspace 目录。
- 配套：`MARINA_SERVICE`/`MARINA_TOKEN`/`TERMINAL_ID` 也 per-session 注入（file-panel HTTP 用）。

### D.3 设计要点

> 本节多项已 [已裁决]，标注于每条。

复用的本质 = 让「当前运行的 session」切换到「某个旧 workspace 目录」，并恢复该目录记录的
文件面板状态。需要五块能力：

1. **稳定可读标识 [已裁决 A：AI 显式命名]**
   - AI 用 `marina workspace bind --name "feature-x"` 给工作空间命名。manifest record 扩展为
     `{closedAt, name, createdAt, pinned, pathScope}`（pathScope 见第 5 条）。schema 升版 + 迁移，
     兼容旧 manifest（旧记录 name 缺失，按未命名处理）。

2. **枚举 API**
   - CLI `marina workspace list [--json]`：main 端暴露 manifest 里未过期/已 pinned 的 workspace
     （含 name/createdAt/closedAt/pathScope）。受附录 H 隐私约束：CLI 给用户/AI 用 OK，但自动
     性能报告仍禁路径。

3. **绑定 = 运行中切换 [已裁决：运行中切换，非建 session 时]**
   - CLI `marina workspace bind --name <name>`（在**当前运行的终端**里执行）→ HTTP 到 main →
     main 把**当前 session** 的 workspace 绑定切换到指定旧目录。
   - **关键技术调整（运行中切换的现实）**：终端子进程的 `$env:MARINA_WORKSPACE` 在 spawn 时就
     固定、运行中改不了。所以要让切换真正生效，CLI `marina workspace`（及 show 等写入操作）
     不能再只读 `$env`，得**改成向 main 查询「当前 terminal（按 TERMINAL_ID）绑定的 workspace」**。
     main 端切绑定后，CLI 后续读写自动指向新目录。`$env:MARINA_WORKSPACE` 退化为初始值/兼容值。
   - 切换后该 workspace **置 `pinned: true`，跳过 7 天回收 [已裁决]**。
   - 「改变工作空间」只改 Marina 的 workspace（放 AI 产物的 scratch 目录），**不影响终端 cwd**
     [已裁决]——workspace 和终端 cwd（用户在哪个项目）是两回事，不能混淆。

4. **文件面板状态持久化 + 自动恢复 [已裁决：要持久化 + 绑定时恢复]**
   - workspace 目录新增 `__marina_state__/file-panel.json`（或并入 manifest），记录当前版本已有
     的文件面板状态：**打开的文件列表（路径 + active）、每个文档的滚动位置**（未来可扩到代码块
     运行结果，但 v1 先做文件列表 + 滚动位置）。
   - 写入时机：文件面板状态变化时（打开/关闭文件、滚动停止 debounce）落盘到当前 workspace。
   - 恢复时机：`bind` 切换到某 workspace 后，main 把该 workspace 的 `file-panel.json` 推给
     renderer，renderer 恢复「打开的 tab + 滚动位置」。用户切回旧工作空间 = 看到上次的文档们。
   - **远程一致性**：状态文件在 workspace 目录（本地 daemon），renderer 通过 IPC 拿，本地/远程
     统一走 backend-data 域。

5. **路径作用域约束 [已裁决：只能绑定相同路径下的 workspace]**
   - workspace 归属于一个**路径**（session 的 pathId / cwd 目录）。AI 绑定时**只能选择当前
     session 所属路径下**的历史 workspace，不能跨路径绑定。
   - 实现：manifest record 带 `pathScope`（绑定时的 pathId 或目录）。`list` 按 path 过滤；
     `bind` 时 main 校验 `targetWorkspace.pathScope === 当前 session.pathId`，不符拒绝。
   - 这条天然消除了「绑定任意/敏感路径」的顾虑——workspace 就只能是受管目录里的有效 workspace，
     且必须同路径 [已裁决确认：不存在「敏感目录」一说]。

### D.4 实现细节（产品决策均已裁决）

- **CLI 改造影响面**：`marina workspace` 从「读 env」改成「查 main」后，离线/服务不可用时如何
  退化？倾向：ping 不通则报错退出（与现有 `show` 行为一致），不悄悄 fallback 到 env。
- **状态快照的粒度**：v1 记录「打开文件列表 + active + 滚动位置」。代码块运行结果（L1 工作态）
  要不要也进快照？倾向 **v1 先不做**（运行结果是会话内工作态，且可能含敏感输出）。
- **快照写入频率/性能**：滚动位置高频变化 → debounce 落盘（如停滚 500ms）；切走面板/关闭
  session 时强制 flush。不能进逐字节热路径（附录 H）。
- **`name` 唯一性**：同路径下重名如何处理？报错 / 加后缀？倾向报错让 AI 改名。
- **pinned workspace 的清理 [已裁决：不自动回收]**：pinned 永不自动回收；只能 AI 显式
  `marina workspace unbind` / `remove`，或用户在设置里手动清。需补一个 `unbind`/`remove` CLI。

### D.5 改动面（最大）

### E.1 路径层级 / 分组

#### E.1.a 目标
- 收藏路径要有**层级结构**，可分组（现在平铺，重度使用后塞不下）。

#### E.1.b 设计要点 + 开放问题（核心决策）
这是**数据模型级改动**，有两种建模思路，必须先选：

- **方案①：引入「分组/文件夹」虚拟节点**（推荐）
  - 新增 `GroupNode`（虚拟容器，`{id, name, childPathIds[]}`），PathNode 仍平铺但带 `groupId`。
  - `bookmarks.json` schema 升版：`{groups: [{id,name,order}], paths: [{...,groupId}]}`，兼容旧
    （无 groupId 的 path 归到「未分组」）。
  - UI：分组可折叠/展开、重命名、拖 path 进出分组。
  - 优点：path 身份不变（id 仍是路径），分组是纯组织层，迁移平滑。
- **方案②：path 之间互相 parent（树）**
  - PathNode 加 `parentId`，path 直接挂另一个 path 下。语义怪（路径 A 是路径 B 的父？），不推荐。

- **分组层级是否无限嵌套**：倾向**只允许一级分组**（分组 → path），避免复杂树 + 拖拽心智负担。
- **临时/最近要不要也分组**：**[已裁决 #13] 只收藏可分组**，临时/最近不可分组（它们是自动推导分类，分组无意义）。
- **折叠态记忆**：分组展开/折叠是 L2 偏好（附录 G），用 `usePanelPreference` 持久化。

#### E.1.c 改动面
- `src/shared/types.ts`：新增 GroupNode / 改 PathNode / PathTree。
- `src/main/path-manager.ts`：getTree 组装分组、reorderBookmarks 扩展到含分组顺序、新增
  group CRUD（addGroup/renameGroup/removeGroup/movePathToGroup）。
- `bookmarks.json` schema 迁移。
- `src/shared/protocol.ts` + `ipc.ts`：group 相关 command。
- `Sidebar.tsx`：`Category`/`PathItem` 改造支持分组渲染 + 折叠。
- 测试：分组 CRUD、迁移、reorder 含分组（path-manager.test.ts 扩展）。

### E.2 拖拽排序

#### E.2.a 目标
- 路径条目、terminal 条目都能**上下拖动**排序；**terminal 条目不能跨路径**。

#### E.2.b 设计要点
- **路径排序**：接现成的 `BOOKMARK_REORDER`（`cmd:bookmark:reorder`），UI 加 dnd 即可（后端已就绪）。
  - 分组内排序 + 跨分组移动（若 E.1 选方案①）需扩展 reorder 协议（带 groupId）。
- **terminal 排序 [已裁决 #15：服务端内存真值，不落盘]**：当前 session 顺序 = sessionToPath
  Map 插入序（≈创建序），无顺序字段。新增：
  - main 端给 `sessionToPath` 旁加 `sessionOrder: Map<pathId, sessionId[]>`（**服务端/daemon
    内存真值，不写磁盘**）；加 IPC `SESSION_REORDER`（`cmd:session:reorder`，{pathId, orderedSessionIds}），
    renderer 拖完发给 main，main 广播更新后的顺序给所有窗口。
  - **为何必须在 main 而非 renderer** [开发者约束]：要保证 ①**窗口关闭再打开**顺序不变、
    ②**远程访问**（另一窗口看同一 session）顺序一致——顺序真值只能在 daemon/main，不能存
    renderer localStorage（否则窗口间/远程不一致）。session 不持久化⇒重启后顺序自然重置
    （新 session 无「上次顺序」可恢复），这是可接受的。
- **terminal 不能跨路径**：数据层已保证（pathId 永不变），**UI dnd 限制 drop target**——只能
  落在同 path 的 session-list 内，拖到别 path 高亮拒绝。这是纯前端约束。

#### E.2.c 开放问题
- **dnd 库 [已裁决 #14：`@dnd-kit`]**：选 (a) `@dnd-kit/core` + `@dnd-kit/sortable`
  （React 声明式、开箱即用、社区最大，与现有代码风格最贴；列表排序是其最稳甜区）。
  备选 Pragmatic DnD / 原生 HTML5 / react-aria 未选。⚠️ 装前在 npm 扫一眼 `@dnd-kit/core` 最近
  发布时间确认仍活跃（联网核验未果）。走 AGENTS.md 边界 2 流程（对话里告知再装）。
- **terminal 顺序持久化 [已裁决 #15：不落盘，服务端内存]**：见 E.2.b——顺序存在 main/daemon
  内存，保证窗口重开/远程一致；不写磁盘（重启重置）。
- **临时/最近路径能否拖序**：**[已裁决 #13] 只收藏可拖序**（后端无 reorder 通道）。

#### E.2.d 改动面
- 新增依赖 `@dnd-kit/core` + `@dnd-kit/sortable`（装前 npm 核活跃度）。
- `Sidebar.tsx`：PathItem/SessionItem 加 draggable + drop zone。
- `src/main/path-manager.ts`：sessionOrder 维护 + `SESSION_REORDER` handler。
- `src/shared/protocol.ts`：`SESSION_REORDER` 通道、reorder 扩展分组。
- 测试：reorder 语义（已有 path-manager.test.ts 可扩展）、跨路径拒绝（renderer 单元）。
