# T05 · Gallery UX 原型 — 怎么 react

> HITL 原型(可丢弃)。打开原型 → 切换 3 个变体 → 回答下面的参数问题。
> 定完参数后写进 `docs/方案-图片表gallery-参数-YYYYMMDD.md`,作为 T09 实现输入。

## 怎么打开

1. 用浏览器打开 `docs/prototypes/gallery-ux-prototype.html`(双击即可,零依赖)
2. 按 **← / →** 或点底部浮动条切换变体
3. 原型模拟了 8 张图:前 4 张本地图(秒加载)、第 5/7 张网络图(模拟 600ms 下载)、
   第 6 张网络图**模拟下载失败**(可点重试)、第 8 张本地图
4. 懒加载窗口已模拟:只加载当前张 ±1,窗口外的图显示骨架

## 三个变体(结构不同,不是换皮)

| 变体 | 主图策略 | 缩略图条 | 失败态 |
|---|---|---|---|
| **A 固定舞台** | 主图区固定 320px 高,`contain` 居中,不撑爆面板 | 固定 56px 缩略图,单行横滚,溢出滚动 | 主图区占位 + 重试按钮 + 指示器 ⚠ 计数 |
| **B 自适应流式** | 主图按图片比例自适应高度(上限 480px),超高缩小 | 64×48 缩略图,自适应宽度,放不下横滚 | 失败折叠成小卡片(不占主图区)+ 顶部计数条 |
| **C 极简覆盖** | 主图 380px 高沉浸式,无缩略图条 | **无缩略图条**,只留左右箭头 + 角落计数 | 失败占位 + 重试,角落 ⚠ 徽章 |

## 需要你裁决的参数(回答即可,选 A/B/C 或"混搭")

1. **主图尺寸策略** —— 选哪个?
   - A:固定高度(320px)contain 居中 → 面板稳定,但竖图留白大
   - B:按比例自适应(上限 480px)→ 图多大显示多大,但每张高度不同会跳
   - C:固定 380px 沉浸式
   - 或者:固定高度但**按首图比例**定(规划 doc A.4 提的选项)?

2. **缩略图条** —— 要哪种?
   - A:固定 56px 单行横滚(视觉稳定)
   - B:64×48 横条
   - C:不要缩略图条(极简)
   - 溢出处理:滚动 vs 翻页 vs 截断?最多显示几张?

3. **网络图失败态** —— 失败时用户看到什么?
   - A:主图区占位 + 重试按钮(显眼)
   - B:折叠小卡片 + 顶部计数(不打断浏览)
   - C:角落徽章(最轻)
   - 超时建议:下载超时多久?(默认 10s?)失败后自动重试一次还是只手动?

4. **懒加载窗口** —— 当前张 ±1 够吗?还是 ±2?(原型默认 ±1)

5. **网络图临时文件清理** —— 下载到 `MARINA_WORKSPACE/__marina_gallery__/`,
   什么时候清?session 销毁时 / workspace 回收时 / 都不清(跟随 workspace)?

6. **其他观感** —— 有没有哪个变体的交互让你觉得"就该这样"?或者 A 的头 + B 的缩略图条这种混搭?

## 回答格式

直接回复,比如:

```
1. 主图:B(自适应)
2. 缩略图条:A(56px 单行横滚,最多 12 张)
3. 失败:A(占位+重试,超时 10s)
4. 懒加载:±1 够
5. 清理:随 workspace 回收
6. 其他:没有
```
