# 方案：侧栏收藏分组（ADR-025）

> 关联：[规划-v0.3.3 § Feature E.1](./规划-v0.3.3-AI交互丰富度-20260801.md) ·
> [Wayfinder ticket #4（T03 grilling）](https://github.com/fexla/marina/issues/4)
> 日期：2026-08-01 · 状态：已实现；2026-08-07 增补 kind ownership 修订

## 1. 背景与目标

收藏路径当前**平铺**，重度使用后塞不下。给它加**一级分组**（虚拟容器组织层），path 身份不变。
**约束**（决策 #12/#13）：方案①虚拟节点 + 只一级 + **只收藏可分组/可拖序**（临时/最近是自动推导分类，不分组）。

## 2. 关键决策（grilling 共识）

| # | 决策 |
|---|---|
| **G1 truth source** | `PathNode.groupId` 作**唯一真相**；`GroupNode = {id, name}`（磁盘/PathTree 中数组位置即顺序，无 order 字段）；`childPathIds` 由 `getTree` 按 groupId 派生给 renderer，不冗余存储 |
| **G2 schema 迁移** | `bookmarks.json` v1→v2：`{version:2, groups:[{id,name}], paths:[...,groupId?]}`；旧 path 补 `groupId=undefined`（归未分组），`groups=[]` |
| **G3 reorder 协议** | **统一分层 reorder**：一个 IPC，payload=完整目标布局 `{ungrouped:[ids], groups:[{id, childOrder:[ids]}]}`；main 校验"所有 bookmark 恰好一次、无重复"后整体替换顺序 + groupId。移动 path 到别的组 = 放进目标组 childOrder，**无单独 movePathToGroup 命令** |
| **G4 CRUD 边角** | `addGroup(name)` / `renameGroup(id,name)`（组名收藏内唯一）/ `removeGroup(id)`（子 path 移未分组，**不删 path**）；**允许空组** |
| **G5 未分组渲染** | 未分组 path **在顶部散开**（隐式块），下面按顺序排列各分组 |

折叠态记忆 = L2 偏好 `usePanelPreference`（附录 G），不在本方案范围（renderer 侧）。

## 3. 数据模型（`src/shared/types.ts`）

```ts
/** 分组虚拟节点。顺序 = 在 PathTree.groups / BookmarksFile.groups 数组中的位置。 */
export interface GroupNode {
  id: string;
  name: string;
}

// PathNodeBase 新增可选字段：
//   groupId?: string;   // undefined = 未分组。仅收藏路径会用。

export interface PathTree {
  bookmarks: PathNode[];
  temporary: PathNode[];
  recent: PathNode[];
  groups: GroupNode[];   // 仅收藏有分组；temporary/recent 恒为 []
}
```

- `PathNode.groupId` 是**唯一真相**。`getTree` 组装时：按 `groups` 顺序遍历，每组的 children = `bookmarks.filter(b => b.groupId === g.id)`（按 bookmarks 数组顺序，即拖序后的顺序）；未分组 = `bookmarks.filter(b => !b.groupId)`。
- 渲染用：renderer 拿到 PathTree 后自己按 G5（未分组顶置 + 分组顺序）排版；`childPathIds` 不进 PathTree（派生即可，避免双真相）。

## 4. bookmarks.json schema v2 + 迁移

```jsonc
{
  "version": 2,
  "groups": [{ "id": "g1", "name": "工作项目" }],
  "paths":  [{ "id": "...", "path": "...", "kind": "local", "addedAt": 0, "groupId": "g1" }]
}
```

- `PersistedBookmark` 加可选 `groupId?: string`。
- `PersistedGroup = { id: string; name: string }`（无 order/addedAt，顺序=数组位置）。
- **迁移**（v1→v2，`PathManager.initialize`）：旧 paths 原样保留、每条 `groupId=undefined`；`groups=[]`。幂等、原子写（JsonStore）、损坏回退默认。沿用既有 `kind` 字段迁移模式。
- groupId 稳定性：groupId 是新生成的 UUID，不与 pathId 复用；删组后其 id 作废（不回收）。

## 5. reorder 协议（`src/shared/protocol.ts` + `src/main/path-manager.ts`）

扩展现有 `BOOKMARK_REORDER`（`cmd:bookmark:reorder`），payload 从扁平升为分层：

```ts
// BOOKMARK_REORDER payload
{
  ungrouped: string[];                       // pathId 有序列表
  groups: { id: string; childOrder: string[] }[];  // 数组顺序 = 分组显示顺序
}
```

- **校验**（`reorderBookmarks` 重写）：`ungrouped` ∪ 各 `childOrder` 的并集必须**恰好等于**当前 bookmarks 的 pathId 集合，无重复、无未知、无遗漏（沿用既有 `InvalidOrderList` 错误语义）。
- **应用**：按 `ungrouped` + 各组 `childOrder` 的**拼接顺序**重排 `this.bookmarks`；按 payload 给每条 bookmark 赋 `groupId`（ungrouped 段=`undefined`，组段=该组 id）。原子替换 + `persistBookmarks` + `emitChange`。
- 旧的"全部未分组"= `groups:[]`, `ungrouped:[全量]` 的特例。
- **不新增** movePathToGroup / reorderGroups / reorderWithinGroup 命令——全走这一份统一布局。

## 6. 分组 CRUD（新增 IPC）

| 通道 | payload | 行为 |
|---|---|---|
| `BOOKMARK_GROUP_ADD`（`cmd:bookmark:group:add`） | `{name}` | 新建 GroupNode（追加到 groups 末尾），返回 `{id}`。重名→报错 |
| `BOOKMARK_GROUP_RENAME`（`cmd:bookmark:group:rename`） | `{id, name}` | 改组名；收藏内重名→报错 |
| `BOOKMARK_GROUP_REMOVE`（`cmd:bookmark:group:remove`） | `{id}` | 删组；其下 paths 的 `groupId` 清空→归未分组（**绝不删 path**） |

- 组名**收藏内唯一**；非空、禁路径分隔符（防歧义）、≤64 字符（与 workspace name 规则一致）。
- **允许空组**（用户先建空组再拖）。
- 这些是低频 CRUD，各自独立 IPC（与高频 reorder 分开）。

- `src/renderer/components/Sidebar.tsx`：`Category`（收藏那栏）渲染未分组块 + 各分组块（分组头：折叠/重命名/删组）；`PathItem` 接 dnd（**dnd 实现归 T08**，本方案只定数据模型 + IPC）。
- 测试：`path-manager.test.ts` 扩展（schema 迁移、分层 reorder 校验、group CRUD、删组子项归未分组、组名唯一）。

## 8. 不做（本期内）

- 不做多级嵌套分组（只一级）。
- 临时/最近不分组、不拖序（无 reorder 通道，#13）。
- 不把 `childPathIds` 存进 PathTree（派生即可）。
- PersistedGroup 不加 `order`/`addedAt`（数组位置即顺序）。
- 分组折叠态不进 bookmarks.json（走 L2 `usePanelPreference`，renderer 侧）。

## 9. 测试要求

- schema v1→v2 迁移（幂等、原子、损坏回退；旧 path 归未分组）。
- 分层 reorder：并集=全量校验（少/多/重复/未知→`InvalidOrderList`）；应用后 bookmarks 顺序 + groupId 正确。
- group CRUD：add（重名报错）、rename（重名报错）、remove（子项 groupId 清空→未分组，path 不丢）。
- getTree 组装：未分组块 + 分组顺序 + 组内 path 顺序正确；空组可见。
- 组名校验（非空/禁分隔符/≤64/收藏内唯一）。

## 10. 2026-08-07 修订：分组由 PathKind 单独拥有

本节**取代**上文 `GroupNode` 无 kind、local/ssh 共用全局分组树、组名收藏内
全局唯一等旧结论；上文保留作为 ADR-025 的历史决策链。

### 10.1 领域规则

- 每个 `GroupNode` 实例只属于一个 `PathKind`：`local` 或 `ssh`。
- local/ssh **共用分组功能、PathManager 模块、renderer 组件和 DnD 算法**，但
  **不共用分组实例或分组树数据**。
- 父组、子组及直接成员 bookmark 必须同 kind；main 是该不变式的权威守门人。
- 组名改为**同 kind 内唯一**；local 与 ssh 可各自存在同名组。
- renderer 当前 segment 只渲染对应 kind 的分组森林。因此 local 空组不会在远程
  segment 出现，ssh 空组也不会在当前电脑 segment 出现。

### 10.2 schema v4 与迁移

`bookmarks.json` 升到 v4，`PersistedGroup.kind` 必填。v1-v3 迁移规则：

1. 按组内直接/后代 bookmark 的 kind 收集证据。
2. 单 kind 组归该 kind；混合组拆成 local/ssh 两个同名、不同 id 的实例，并
   重写相应 bookmark.groupId。
3. 完全无成员证据的空组继承最近的单-kind 祖先；无法推断的根级/mixed 子树空组
   回落 local。该 fallback 是兼容政策，不声称能恢复旧空组的创建意图。
4. 引用不存在分组的 orphan groupId 清回未分组，避免收藏从 UI 消失。
5. 迁移结果写回 v4；导入旧 archive 走同一迁移，非法形状仍整体拒绝。

### 10.3 reorder 与双视图

- `BOOKMARK_REORDER` 仍提交一份覆盖**全部 path + 全部分组**的全量布局。
- renderer 同时持有 current-kind 可见树与 backend 全量树：可见树只用于渲染、
  菜单、碰撞；全量树用于生成 payload。
- 可见插槽映射到全量 index，保证拖动 local 项时 ssh 项的归属、父子关系和相对
  顺序不丢失，反之亦然。
- main 先完整验证组/path 全量覆盖、单父、无环、同-kind membership，再原子替换；
  失败不得污染内存状态。

### 10.4 IPC

`BOOKMARK_GROUP_ADD` payload 改为 `{name, kind, parentId?}`；`kind` 为 required。
`GroupNode.kind` 通过 snapshot / `evt:path:tree-updated` 下发。该变更不兼容旧 daemon，
因此 `PROTOCOL_VERSION` 升为 4。
