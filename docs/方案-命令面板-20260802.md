# 方案：命令面板（Command Panel）（ADR-028）

> 状态：已决策（grilling 定稿，2026-08-02）
> 关联：wayfinder map #1 Feature G；解锁实现 task（T17）
> 参考机制：ADR-024（workspace 状态持久化）、ADR-021（后台调度）、ADR-023（CodeBlockRunner）

## 1. 背景与动机

### 1.1 用户意图
终端被 AI coding agent（Claude Code / Pi / Codex）占用，是瀑布式聊天框，没法用来"瞄一眼"
某个命令的状态输出（如 wayfinder map/ticket、构建日志、git log）。用户希望在右 dock 有一个
面板，让 AI 推送一条指令，Marina 跑它、把结构化输出渲染进面板、可周期刷新，**不占用终端**。

### 1.2 产品定位
和「已打开」「Git」「文件树」同属**右 dock 面板群**——补足"终端被占着、没法瞄一眼"的观察
需求。命令面板补的是"看任意命令的结构化输出"这一格。

### 1.3 不做的（哲学边界）
- **不做 map/ticket 专用面板**——map/ticket 只是命令面板的第一个用例（配 `marina map` 或
  `gh issue list`），不内建任何 GitHub 耦合，避免"跨 session 上下文累积 / kanban"红线
  （软件定义书 13.2 第 7 条）。
- **不做用户预配命令的设置页**——命令由 AI 推送（program-push），不是用户静态配置。
- **不做内联命令输入框**——临时敲命令用终端；面板只承载"已推送的指令 + 周期重跑"。

## 2. 决策

### D1. 架构：独立第 4 面板，trigger=program-push
- panel id = `command`，在 `panel-registry.tsx` 注册；main 端 `DOCK_LAYOUT_RULES` 同步。
- trigger 类型 = **`program-push`**（和「已打开」同构，**不是**新类型）。
- 不与 FilePanel 合并：FilePanel 语义是"文件"（tab/watcher/requestActivation 按文件设计），
  命令输出不是文件，混在一起要加一堆分叉。

### D2. 数据流：AI 推送任意命令字符串
```
AI 执行 marina run "<任意命令字符串>"
  → POST /run（MARINA_SERVICE HTTP server，Bearer 鉴权，同 /open-file）
  → CommandPanelService 收到，按当前 session 的 workspaceId 加一条指令到列表
  → 立即跑一次（复用 CodeBlockRunner.run，不经 PTY，在 session.currentCwd 下）
  → 输出 emit 给 renderer → 渲染进命令面板（markdown）
  → 按该指令的刷新策略周期重跑
```
- **指令形态只有一种：任意命令字符串**。"引用内置脚本"不是独立形态——它就是一条命令
  字符串（如 `bash /resources/panel-scripts/map-github.sh`）。第一版可不带任何内置脚本。
- 安全：AI 本就在终端有 shell 权限，把输出导流到面板不增加权限面。

### D3. 执行：复用 CodeBlockRunner + bash
- 执行内核 = `CodeBlockRunner.run(input)`（ADR-023，不经 PTY、shell 绝对路径、UTF-8/GBK、
  SSH 拒绝、远程 daemon 路由、生命周期清理、输出聚合回推）。
- 统一执行语言 = **bash**（最通用，macOS/Linux 原生、Windows 靠 Git Bash）。bash 里可调用
  .ts/.py 等脚本（`node map.ts` / `python map.py`）。
- 内置脚本（可选，后续增量）：放 `extraResources/panel-scripts/`（仿 shell-hooks/skills），
  启动扫描注册为便利文件，AI 用命令字符串调用。第一版可不实现。

### D4. 多 tab + per-指令 两维刷新策略（2026-08-07 勘误）
- **多 tab**：一个命令面板可同时挂多条指令（像「已打开」多文件），AI 推第二条新增 tab。
- **前后台范围与刷新间隔是两个独立维度，不得再混成一个枚举/下拉**：
  1. `scope`：`foreground`（仅当前可见 tab 自动刷新）/ `background`（tab 隐藏时仍刷新）；
  2. `interval`：`manual` / `5s` / `30s`，只回答“多久刷新一次”。
- 新指令默认 `foreground + 30s`；program-push 本身立即跑一次。`manual` 时不注册周期 task，
  仍可点“立即刷新”。
- 顶部 toolbar 分成三个职责单一的控件：**前台/后台 toggle** + **刷新间隔 select** +
  **立即刷新按钮**。切换 scope 不得偷偷改 interval，切换 interval 也不得改 scope。
  运行期间按钮禁用，刷新图标旋转并显示“刷新中”；状态提示属于 toolbar，不插进输出正文。
- `CommandEntry.output` 只表示**最近一次已完成结果**。新一轮 stdout/stderr 先写 main 内部有界
  pending buffer，运行期间旧 Markdown 保持可见且可选择；退出后原子替换。取消/被新 run 取代
  时丢弃 pending，绝不把半截输出覆盖到已完成结果。
- demand 映射：active tab + 面板可见为 HOT；`foreground` 的隐藏态为 NONE；`background`
  的隐藏态为 WARM。只有 active foreground 指令能拿 HOT，其他 foreground tab 必须停。
- 调度统一走 `BackgroundWorkScheduler`（ADR-021，recursive setTimeout、全局并发上限、
  显式清理），HOT/WARM 使用用户所选的同一个 interval；窗口关闭/owner 释放清 consumer。
- 兼容：早期 `command-panel.json` v1 的
  `foreground/background-30s/background-5s/manual/off` 在恢复时迁移为 v2 `refreshPolicy`；
  IPC 因字段删除与新 renderer 必需字段曾升级为 **protocol v3**（当前仓库随后因 Group kind
  必填已到 v4），握手拒绝旧 daemon 混用。

### D5. 渲染：markdown
- 复用 `MarkdownViewer`（react-markdown + remark-gfm），白嫖表格、可点链接（方案 B）、
  代码块一键执行。
- 命令输出容器必须显式恢复 `user-select:text`，让共享 `MarkdownCodeBlock` 的“选中代码片段
  → 浮出运行按钮 → 只执行选中内容”交互在命令面板同样生效；普通文本不自动当命令执行。
- 纯文本输出也是合法 markdown，不会更差。

### D6. 状态持久化：套用 ADR-024，独立文件
- **位置**：`<workspace>/__marina_state__/command-panel.json`（独立文件，**不并入**
  file-panel.json——两个 panel 语义独立、写入频率可能不同，分开避免 churn 互相影响）。
- **存什么**：commands（指令列表）/ active / 每条的刷新策略 / （可选）最后一次输出。
- **写入时机**：指令列表变更 debounce 落盘；切走面板/关 session/切 bind 强制 flush；不进
  逐字节热路径（附录 H）。仿 file-panel.json（ADR-024 §2.6）。
- **恢复**：bind 切到某 workspace 后，main 读 command-panel.json 推给 renderer 恢复；
  缺失则跳过。
- **身份**：挂在 workspaceId 上（解耦 sessionId，main 维护 `Map<sessionId,workspaceId>`）。
- **ADR-024 同步**：ADR-024 §7 原文"快照只记文件面板状态，git/文件树不进"需扩展为
  "文件面板 + 命令面板"。

### D7. SSH session：拒绝
- 走 `SshUnsupported`（和 Git 面板、CodeBlockRunner 对称）：SSH session 的 cwd 是远程路径，
  本地 daemon 无法在第三台机器 spawn。SSH session 时命令面板 leaf 不出现或显示拒绝提示。

## 3. 改动清单（实现 task 参考）

**main**
- `src/main/command-panel-service.ts`（新建）：按 workspaceId 存指令列表 + 策略 + 持久化
  （command-panel.json 读写）、执行（复用 CodeBlockRunner）、后台调度
  （BackgroundWorkScheduler per-指令 task）。仿 FilePanelService。

- `src/main/ipc.ts`：注册命令面板相关 IPC（查状态/更新策略/立即刷新/关 tab）。
- `src/main/session-manager.ts`：布局树加 `command` leaf；`createSessionLayoutTree` 联动。

**renderer**
- `src/renderer/components/command-panel/CommandPanel.tsx`（新建）：多 tab + toolbar +
  输出区（复用 MarkdownViewer）。仿 FilePanel + GitPanel。
- `src/renderer/components/layout/panel-registry.tsx`：注册 `command` panel。
- 组件外缓存（仿 `git-status-cache.ts`）：切面板再切回不丢、<16ms。
- `usePanelUiState`（L1）/ `usePanelPreference`（L2）按附录 G 用。

**shared / CLI**
- `src/shared/protocol.ts`：COMMAND/EVENT channels（`cmd:command-panel:*`、`evt:command-panel:*`）。
- `src/skills/show-in-marina/marina*`：加 `run "<cmd>"` 子命令 → `POST /run`。

**打包**
- `electron-builder.yml`：`extraResources` 加 `panel-scripts/`（第一版可空目录）。

- [ ] 推第二条指令 → 新增 tab，两条并存
- [ ] tab 切换：切走的 `foreground` 指令停止自动跑；`background` 指令继续按间隔跑
- [ ] toolbar 的前台/后台 toggle 与刷新间隔 select 可独立修改，互不重置
- [ ] `manual` 不自动跑，但“立即刷新”可用
- [ ] 刷新运行期间旧结果保持可见且可选择，toolbar 显示旋转图标与“刷新中”
- [ ] 刷新退出后用本轮完整 stdout/stderr **原子替换**上一轮结果，不追加、不闪空、不显示半截
- [ ] 输出中的 runnable fenced code block 可选中单行/片段并只运行所选内容
- [ ] 关 Marina 重启 / bind 切换 → 指令列表恢复

- [ ] typecheck + lint + test 通过；后端模块测试覆盖（AGENTS §5）

## 5. 风险与边界
- **per-指令 后台调度**：多条指令都开后台轮询可能 spawn 压力大——靠 BackgroundWorkScheduler
  全局并发预算（默认 1）+ demand 兜底；性能指标只记固定 aggregate（附录 H）。
- **输出体积**：命令输出可能很大——复用 CodeBlockRunner 的 OUTPUT_FLUSH_BYTES（64KB 聚合）
  + MarkdownViewer 的 2MB 截断。
- **指令安全**：AI 推任意命令——不增加权限面（AI 本有 shell），但 command-panel.json
  存指令字符串时注意隐私（不记入自动性能报告，附录 H）。
- **与 ADR-024 的耦合**：依赖 workspace 持久化机制已落地（Feature D / T10 实现中）。
  若 T10 未完成，命令面板的持久化部分需等 T10。

## 6. 不在本次范围
- 内置脚本库（map-github 等）——第一版纯任意命令字符串，脚本作后续增量。
- 用户自加脚本（sandbox 考虑）——后续。
- 命令历史 / 命令模板——不做（违背"不累积"）。
