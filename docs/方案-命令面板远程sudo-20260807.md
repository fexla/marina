# 方案：命令面板远程 sudo（SSH 服务器，Marina 临时托管 sudo 密码）

> 状态：**设计定稿**（2026-08-07，二次修正：弃用上一版 Windows UAC 框架）
> 关联：ADR-028（命令面板，需反转 D7「拒 SSH」）、ADR-023（CodeBlockRunner）
> 动因：用户在**远程 Linux 服务器**（经 SSH）上用命令面板跑 sudo 命令，要 Marina **临时存 sudo 密码**后执行。

---

## 0. 上一版错在哪（避免重蹈）

上一版把「sudo」等同于 Windows UAC，设计了 UAC broker / 输出文件中转 / 放行卡 / 设置开关 —— 全错。真实场景是**远程 Linux 服务器的 sudo**：没有 UAC，没有提权 broker，就是 Linux `sudo -S` 从 stdin 读密码。Marina 托管密码 = 把用户本来要手敲的密码暂存在内存里，每次 sudo 命令经 stdin 喂给远程 `sudo -S`。**与权限面无关**（用户跑的是自己授权范围内的 sudo），纯自动化 + 输出回捕。

---

## 1. 框架

**sudo 不增加权限面。** 用户在自己的服务器上跑自己账号能跑的 sudo，Marina 只是替他暂存密码、代他敲。密码托管是便利，不是提权。

**唯一价值**：终端被 AI 占着，用户要瞄一眼 / AI 要读到一个 sudo 命令的输出，不必另开终端、不必手动敲密码、不必复制输出回贴。命令面板本来的「输出导流」价值（ADR-028 D2）原样延伸到远程 sudo 场景。

**关键区别于 Windows 方案**：
- 无 UAC、无 broker、无需输出文件中转 —— `ssh ... 'sudo -S ...'` 的 stdout/stderr 直接经 child_process 管道流式回捕，**复用 CodeBlockRunner 现有流式机制，零损失**（代码块也照样流式）。
- 密码托管后，sudo 命令**可自动刷新**（不像 UAC 每次弹窗）—— sudo -S 每次静默喂密码即可，无 per-run 交互。

## 3. 交互逻辑

### 3.1 sudo 密码：一次录入，内存托管，按 profile 隔离

- **录入**：命令面板 toolbar 一个 🔑「sudo 密码」按钮（masked 输入）；或当一条 sudo 命令到达而无密码时，面板内联弹出输入。两种都做（按钮=主动，内联=被动）。
- **作用域 = SSH profile**（host+username 决定的远程用户）。同一服务器的所有 session 共享一份；换服务器重新录入。Map<profileId, string> 存在 main 内存。
- **清除时机**：① 应用退出（内存释放）；② 用户点「忘记密码」；③（可选）空闲超时，默认关。**绝不**落盘 / 进日志 / 进 command-panel.json / 进性能报告（附录 H 红线）/ 放 env / 放 IPC 事件 payload。
- **不做 safeStorage**：safeStorage 是给**落盘**密钥加密的；sudo 密码**只在内存**，无需加密落盘。比 daemon-credentials 更简单。

### 3.2 标记 sudo：per-command toggle

- 人：对一条命令 tab 或代码块翻上 🛡 sudo toggle。
- AI：`marina run --sudo "<cmd>"`（CLI 加 `--sudo`，透传 `POST /run` body `{sudo:true}`）。

### 3.3 执行流（人 / AI 统一）

密码**已存**：
- sudo 命令到达 → 立即在远程跑（`ssh profile 'sudo -S -p "" <cmd>'`，stdin 喂密码）→ 输出流式回面板。
- AI 的 `marina run --sudo` 同步拿到 stdout/stderr/exitCode，与非 sudo 命令体验一致。
- **可自动刷新**：密码托管后 sudo -S 静默喂密码，无 per-run 交互，刷新策略与普通命令一致。

密码**未存**：
- sudo 命令到达 → 面板内联弹「需要 sudo 密码」masked 输入。用户录入 → 立即跑。
- AI 的 `marina run --sudo` **阻塞**到用户录入 + 跑完（或超时返回明确码）。这是正确语义：没密码就跑不了 sudo，必须等用户。
- **关键**：这个阻塞**每个服务器只发生一次**。密码存下后，该服务器后续所有 sudo 命令（人 / AI）直接跑，不再等。这正是「临时存密码」的价值 —— 把密码录入摊销到一次。

### 3.4 远程非 sudo 命令一并支持

既然要打通远程执行，非 sudo 命令也该能在命令面板跑（`ssh profile '<cmd>'`，无需密码、无需 stdin）。这是 sudo 功能的自然前提，也让命令面板在 SSH 会话上整体可用（反转 D7）。代价小（同一个 exec 分支，sudo=false 不喂密码）。

## 4. 执行路径（CodeBlockRunner SSH-exec 分支）

在 `run()` 里替换现在的 `SshUnsupported` 拒绝（`code-block-runner.ts:257-261`）为一个 SSH-exec 分支：

1. `pathRefFromId(pathId)` → 拿到 `{profileId, remotePath}`。
2. `sshProfileManager.getInternal(profileId)` → 连接参数（host/user/port/key/proxy）+（password 认证时）解密出的 SSH 密码。
3. 组 argv：**去掉 `-tt`**；`ssh -p <port> [-i key] [-J proxy] [-o ControlMaster...] <user@host> '<remote>'`。
   - remote 串：`cd <shQuote(remotePath)> && ` +（sudo?`sudo -S -p '' `:``）+ `<cmd>`。
   - 命令本体经 `shQuote` 单引号包裹，不嵌套进额外 shell 字符串层 —— 转义安全（复用 `session-manager.ts` 的 `shQuote`）。
4. 认证：key/agent → 无需额外；password 认证 → 复用 `sshpass -e`（env SSHPASS，既有模式）；sshpass 缺失 → 友好报错并建议改用 key 认证。
5. spawn：`child_process.spawn(ssh, argv, { stdio: ['pipe','pipe','pipe'], env, windowsHide:true })`。
   - sudo：写 `<sudoPassword>\n` 到 stdin 后 `end()`。
   - 非 sudo：stdin 立即 `end()`（或不开）。
6. **复用 `pipeOutput`**：stdout/stderr 64KB/100ms 聚合、UTF-8/GBK 解码、exit 处理、run map FIFO、stop/removeSession/removeClient 清理 —— 全部白嫖，零新机制。
7. 错误映射（新增）：ssh exit 255 = 连接失败；sudo 输出含 `a password is required` / `incorrect password` = 密码错（清掉内存密码、标 suspicious、提示重新录入）；`sudo: sorry, you must have a tty` = **requiretty 服务器**（见 §6 局限）。

CommandPanelService 几乎不动：`RunCommandPayload` / `RunCodeBlockPayload` 加 `sudo?: boolean`；passthrough 到 runner。命令面板 leaf 对 SSH 取消隐藏（`session-manager.ts` 三处 + ADR-028 D7 反转）。

## 5. 密码托管实现（新模式）

- 新模块 `src/main/sudo-password-store.ts`：`Map<sshProfileId, string>` + `get/set/has/clear` + 事件通知（密码状态变化让 renderer 更新 🔑 按钮态）。
- IPC：`cmd:sudo-password:set` / `clear` / `has`（has 只回 boolean，永不回密码本身）。
- 进程退出自动释放（内存即清）。可选：`setTimeout` 空闲清除（默认关）。
- **不进 safeStorage、不落盘、不序列化、不进任何日志/perf 报告/event payload**。
- 信任边界 = main 进程（与既有 SSH 密码、daemon token 同一界）。进程被攻破则全泄，sudo 密码不比它们更敏感。内存内再加密（XOR+随机 key）属表演，v1 不做。

**远程 daemon 场景**：SSH session 的 ssh 进程跑在 daemon 机上，sudo 密码须存 daemon 内存。renderer 录入 → 经 WS 发 daemon（与既有 SSH 密码解密同处 daemon 的信任界一致；WS 走 token 鉴权）。v1 接受；若需更严，未来可限制「sudo 密码只存本机 session」。

## 6. 已知局限（诚实写明）

- **`requiretty` 服务器**：sudoers 设了 `Defaults requiretty` 时，`sudo -S` 因无 TTY 失败。Marina 的 exec 走管道不给 TTY（给 TTY 就没法流式回捕）。检测到该错误明确提示「此服务器 sudo 要求 TTY，命令面板 sudo 不支持，请在终端里跑」。现代发行版默认 `!requiretty`，罕见。
- **密码错的判定**：靠 sudo 的 stderr 文本匹配（`incorrect password` / `a password is required`），非结构化。匹配到就清密码重录；匹配不到则当普通失败。可能漏判，但不会误提权。
- **命令需要 stdin 时**：sudo -S 会先吃掉一行密码，之后命令的 stdin 是 EOF。绝大多数命令面板命令不读 stdin；读 stdin 的命令不适用（在终端里跑）。
- **password 认证 + 无 sshpass**：远程 exec 跑不了（ssh 会卡等 TTY 输入）。建议用户用 key 认证。

## 7. 我已定的决策（除非你否决）

| 决策 | 选择 | 理由 |
|---|---|---|
| 密码作用域 | per SSH profile | 密码属远程用户(host+user)，同服务器共享，换服务器重录 |
| 自动刷新 | sudo 命令允许自动刷新 | 密码托管 = 无 per-run 交互，与 UAC 不同 |
| 远程非 sudo 命令 | 一并支持 | sudo 的自然前提，让命令面板在 SSH 整体可用（反转 D7） |
| 密码持久化 | 不持久化，仅内存 | 用户明示「临时」；app 退出即清 |
| 空闲超时清除 | 默认关，可配 | 避免用户正用着被清；sudo 自身有 timestamp_timeout 兜底 |
| 内存内再加密 | 不做 | main 进程是信任界，再加密是表演 |
| 输出捕获 | 直接 ssh exec 管道流式 | 无 UAC，复用 CodeBlockRunner 既有流式，零损失 |

**需要你确认的 1 点**：远程 daemon 场景 sudo 密码经 WS 发 daemon 存 daemon 内存 —— 接受？（与既有 SSH 密码同信任界；不接受则限制本机 session。）
