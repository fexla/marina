# 隐藏顶部标签栏后的交互问题(用户视角)

**功能**:设置 → 外观 → 隐藏顶部标签栏
**本质变化**:顶部那一条标签栏整个消失——包括每个终端的标签页、右边的「+ 新建」、每个标签上的「× 关闭」、标签右键菜单。终端主区往上挪、多占一行。

下面只讲**用户做了什么、看到了什么、哪里别扭**。

---

## 场景一:关掉正在看的终端 → 掉进「新建终端」页 ⭐ 最痛

**操作**:你有 3 个终端开着(都在同一个目录下),正在看其中一个。去侧栏右键把它「关闭」。

**预期(标签栏在时的直觉)**:关掉当前这个,主区自动切到同目录的另一个终端,继续干活。

**实际(隐藏后)**:主区直接变成「新建终端」空白页——即使还有 2 个终端开着。你必须再去侧栏手动点一个 session,才能回到终端。

> 为什么痛:打破了「关一个、看下一个」的肌肉记忆。用户会以为终端全没了,或者以为要重新建。明明还有终端开着,却被踢到一个新建页。

---

## 场景二:新建终端 —— 没了显眼的「+」,而且双击只能建默认款

**原来的操作**:点顶部「+」→ 出现新建页 → 挑模板(Shell / Claude Code / …)→ 建好。一步到位,且能选模板。

**隐藏后能怎么做**:
- **双击侧栏目录** → 立刻建一个终端。**但只能用默认模板**,选不了 Shell/Claude Code/其它。想换模板?得走下一种。
- **单击侧栏目录** → 进「新建终端」页 → 挑模板按钮 → 建好。能选模板,但变成两步。
- 侧栏分类的「+」→ 选文件夹 → 建(走临时分类)。

**别扭在哪**:
- 顶部那个一眼就能看到的「+」没了,新建的入口变得不显眼,新用户会愣一下「怎么新建终端?」。
- 最快的双击只能建默认款;想建 Claude Code 这种,必须绕到单击进新建页再挑。

---

## 场景三:关闭终端 —— 「×」没了,得去侧栏翻

**原来的操作**:终端就在眼前,点它标签上的「×」,关掉。

**隐藏后**:终端上没有任何关闭按钮。只能去**侧栏**找到那个 session、右键 →「关闭」。

**别扭在哪**:终端明明就在主区正中央显示着,你想关它,却要把视线挪到左侧、在一堆 session 里把它认出来、右键、关。尤其 session 多的时候,「在侧栏里找出当前这个」本身就是个负担。

---

## 场景四:切换终端 —— 只能走侧栏(设计如此,但和上面叠加就别扭)

隐藏标签栏后,**切换终端的唯一方式是点侧栏的 session**。这本身是刻意的(标签栏藏了,自然用侧栏切)。

单看切换没问题。但它和场景一叠加就很别扭:你关掉一个终端 → 掉进新建页 → 又得去侧栏点一个才回到终端。连续两个动作都依赖侧栏,打断感很强。

---

## 场景五(小):双击新建时可能闪一下「新建终端」页

双击侧栏目录建终端时,主区有时会先闪过一下「新建终端」空白页,然后终端才出来。一闪而过,但能注意到。(走「单击进新建页 → 挑模板按钮」这条路则不会闪。)

---

## 一句话总结

隐藏标签栏拿掉了「+ 新建」「× 关闭」「标签切换」三样常驻入口,但**主区没有补回任何替代入口**,而且**关闭当前终端后不自动切到同目录的另一个终端**。用户失去的不仅是那一行高度,还有就地新建/关闭/续看的能力,全被赶到侧栏去完成。

---

## 想往哪个方向改?(交互层面,等你定)

1. **关闭后自动续看**:关掉当前终端时,自动切到同目录另一个开着的终端,而不是掉进新建页。——直接治场景一(最痛)。

2. **主区加常驻的「新建 / 关闭」按钮**:不依赖标签栏,藏了标签栏也能就地新建/就地关闭当前终端。——治场景二、三。

3. **双击目录支持选模板 / 消除闪烁**:让最快的入口也能选模板,并修掉场景五的闪。——治场景二、五。

三者互不冲突。我的建议:**先做 1(止血)+ 2(补回入口)**,3 作为打磨。
