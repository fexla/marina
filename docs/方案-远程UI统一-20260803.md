# 方案:两种远程模式的 UI 统一(SSH + 远程后端)

> 日期:2026-08-03 · 状态:已拍板(grilling 文档 `远程UI统一-grilling.md` 全部按推荐走)
> 对应文档:软件定义书 §14(SSH 模式 §14.1-14.8 / 远程后端 §14.9)
> 目标版本:v0.3.3 后续(v1.14 文档标注)

---

## I. 背景

Marina 有两种远程模式,界面逻辑长期不统一:

| | **SSH 远程**(§14.1-14.8) | **Marina 远程后端**(§14.9) |
|---|---|---|
| 本质 | 连"没装 Marina 的机器" | 用"另一台机器上的完整 Marina" |
| 连接粒度 | **路径级**(`ssh:pathId` 进路径树) | **窗口级**(每窗口后端) |
| 入口 | Sidebar 顶部 segmented「本地/远程」 | Sidebar 底部 footer「远程」按钮 + 菜单 |
| 设置 | 条件分类「远程」 | 常驻分类「远程连接」 |

用户反馈的问题:**首页两种远程的交互方式不统一、设置页排布不统一**。

### 已定约束(不推翻)

1. **每窗口后端**(阶段2 架构修正):daemon 连接必须开新窗口,不可能像 SSH 一样在当前窗口起 session。两者**不在同一抽象层**(路径 vs 窗口),交互不可能完全抹平。
2. **本地用户视野不变式**(§14.2):无远程配置时 UI 与 beta.9 100% 一致。
3. 两种模式并存是产品决策(§14.9.1),不是过渡态。

### 现状不一致清单(代码证据见 grilling 文档)

- **U1/U2 入口分裂**:SSH 走 segmented + 路径树;daemon 走 footer 菜单 + 开新窗口
- **U3 设置两个同名分类**:「远程」(SSH,条件显示,平铺风格)vs「远程连接」(daemon,常驻,子区块风格)
- **U4 footer 按钮无条件渲染** → 本地用户也看得到远程元素,违反 §14.2
- **U5 「远程」一词过载**:segmented 段 / footer 按钮 / 两个设置分类四个名字指三种东西
- **U6 远程窗口内设置页混两套数据源**:「远程连接」面板(local-control)操作客户端本机,其它分类操作 daemon,无区分;列表与 CRUD 数据源还不一致
- **U7 daemon 窗口主区没有"我在哪"上下文**:只有标题栏小字

---

## II. 统一模型

**「远程」= 一个概念、一个入口、一个设置分类。** "SSH 服务器"和"Marina 电脑"是它下面的两种类型,视觉/文案可区分;显示条件单点定义(视野守护);远程窗口里"我在操作哪台机器"永远有上下文。

不抹平技术差异(路径级 vs 窗口级是架构事实),只统一用户心智。

---

## III. 方案细节

### III.1 设置页:合并为一个「远程」分类,三子区块

- **删除**常驻分类 `remote-connection`(`settings.category.remoteConnection` 文案废弃)
- 「远程」分类(`remote`)内部三个子区块(统一 `settings-subsection` 布局):
  1. **SSH 服务器** — 现有 RemotePanel 全部内容(profile CRUD + 远程文件夹 + agent 状态 + ssh_config + ControlMaster + known_hosts + 始终显示远程入口开关)
  2. **Marina 电脑** — 现有 RemoteConnectionPanel 区块 B(已保存电脑列表 + 添加/编辑表单)
  3. **允许远程连接** — 现有区块 A(运行状态 / 端口 / 连接密码)
- 区块 2/3 顶部(远程窗口时)加说明条:**「以下设置属于本机,不是正在连接的 <电脑名>」**(Q4-A)
- 显示条件换统一 helper(§III.4)

### III.2 Sidebar:远程 tab 加「Marina 电脑」区段,删 footer 按钮

- segmented「远程」tab 顶部新增「Marina 电脑」区段:列出**客户端本地**已保存电脑(server 图标 + 显示名 + host),点击 → `WINDOW_CREATE + backendProfileId` 开新窗口(`hasToken=false` 灰显 + 提示"去设置填写");空态显示「去 设置 → 远程 添加」
- **删除 footer「远程」按钮**(「设置」按钮保留)
- segmented 显示条件改为 `hasAnyRemote`;aria-label「路径来源」→「本地 / 远程」
- 区段数据源 = `state.remoteBackendProfiles` —— store 已保证它在任何窗口(含远程窗口)都是**客户端本机**保存的电脑列表:snapshot/load 前用 local-control `REMOTE_PROFILE_LIST` 覆盖 daemon 的 snapshot 值,之后由本地 `REMOTE_PROFILES_UPDATED` 事件持续同步(见 `store.tsx` snapshot 处理,已有实现,本次不改)。**不需要新 hook** —— 远程窗口里"这台电脑能连的电脑"永远是客户端本机保存的(U6 修复,此前 WindowChrome/设置面板各自拉取,这次统一为 state)

### III.3 主区:远程窗口上下文行

- 远程窗口(`window.api.backendProfileId` 非空)的 WelcomeState / EmptyPathState 顶部加一行:**「正在操作 <电脑名> 上的 Marina · 关闭窗口断开」**(Q6-A;复用 WindowChrome 的 REMOTE_PROFILE_LIST 拉取模式,抽成 hook)
- SSH 区段(连接/tmux 按钮)保留不动

### III.4 显示条件统一 helper(视野守护)

`src/shared/remote-visibility.ts`:

```ts
hasAnyRemote = hasSshProfiles || hasDaemonProfiles || enableRemote || daemonRunning
```

- `hasSshProfiles` = `sshProfiles.length > 0`
- `hasDaemonProfiles` = `remoteBackendProfiles.length > 0`
- `enableRemote` = `settings.advanced.enableRemote`
- `daemonRunning` = `remoteDaemonStatus.running`

使用处(全部替换原各自条件):
1. Sidebar segmented(原 `hasSshProfiles || enableRemote`)
2. 设置页 `buildVisibleCategories`(原同左)
3. footer 按钮 — 已删除,无第三处;但 helper 保持三处共用形态 + invariant 测试(对齐 §14.2"由 invariant 测试守护"精神)

注:远程窗口内 snapshot 来自 daemon,故 helper 在远程窗口反映的是 daemon 的远程配置 —— 与窗口内容一致,正确。

### III.5 命名统一

| 位置 | 旧 | 新 |
|---|---|---|
| 设置分类 | 「远程」(SSH)+「远程连接」(daemon) | 「远程」(一个) |
| 设置子区块 | — | 「SSH 服务器」「Marina 电脑」「允许远程连接」 |
| Sidebar 区段 | footer「远程」按钮 | segmented 远程 tab 内「Marina 电脑」区段 |
| segmented aria | 「路径来源」 | 「本地 / 远程」 |
