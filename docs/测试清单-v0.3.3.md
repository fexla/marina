## 已完成可实测项

### SCROLL-2 · alt-screen TUI 运行时滚动条不再跳到顶部

**改动**:`src/renderer/components/TerminalView.tsx` onScroll 滚动位置记忆加
`if (buf.type !== 'normal') return` 守卫,gate 掉 alternate buffer。

**背景**:运行 Claude Code / Pi / vim 这类 alt-screen TUI 时,终端滚动条偶发
跳到 scrollback 最顶部。根因是 xterm 在 `?1049h`/`?1049l` 切换 buffer 时会 fire
一次 onScroll,旧逻辑没区分 buffer 类型,把切换瞬间的 ydisp 当用户滚动记进 store,
replay 重建时 scrollToLine 把视口拉到顶部。详见
`docs/issues/scroll-2-alt-buffer-viewport-jump-to-top.md`。

**测试步骤**:

1. **基线 · plain shell 不受影响**
   - 开一个终端,跑 `for ($i=0; $i -lt 200; $i++) { Write-Output "line $i" }`(或
     任何产生长输出的命令)。
   - 滚到上面看一会儿历史(停在中间某行),再滚回底部。
   - 切到另一个终端再切回。
   - **预期**:切回时视口停在离开时的位置(如果你停在看历史,就还在那里;贴底就贴底)。
   - **失败现象**:视口跳到 scrollback 最顶部,或跳到底部(而你明明在看历史)。

2. **Claude Code · 普通切换不跳顶**(主场景)
   - 开一个终端,运行 `claude`(或 `pi`)。
   - 在 TUI 里交互几轮(让它进出 alt screen 几次:开 pager、看 diff、子命令等)。
   - **不退出** Claude Code,切到另一个终端,再切回。
   - **预期**:切回时 TUI 界面正常,视口在 Claude Code 当前屏幕,不在 scrollback 顶部。
   - **失败现象**:切回时视口跑到一个空的/旧的 scrollback 顶部,Claude Code 的 TUI
     画面不见了或错位。

3. **Claude Code · 缓存淘汰后 replay 不跳顶**(最关键,直接命中根因路径)
   - 开一个终端跑 `claude`,让它进入 TUI 中段(有内容)。
   - **保持它运行**,连续新开终端直到超过 TerminalDeck 缓存上限(10 个),把这个
     Claude Code 终端**挤出缓存**(可以开 11 个终端,再切回第 1 个)。
   - 切回那个 Claude Code 终端(此时会触发 replay 重建,而不是普通 deck 复用)。
   - **预期**:replay 后视口落在 Claude Code TUI 的当前状态(贴底),不跳到 scrollback
     顶部;TUI 画面、光标位置正确。
   - **失败现象**:replay 后视口跳到 scrollback 最顶部(一片空白或旧 shell 历史)。

4. **进 TUI 前看过历史 · 也不污染**(根因针对性验证)
   - 开终端,滚到上面看历史,**故意不滚回底部**,直接输入 `claude` 启动 TUI。
   - 在 TUI 里待一会儿,退出 TUI(`exit` 或 `/exit`)回到 shell。
   - **预期**:回到 shell 后视口在 shell 当前提示符(贴底),正常。
   - 切走再切回(触发或模拟 replay)。
   - **预期**:切回后视口仍在 shell 当前位置,不会因为你"进 TUI 前看过历史"就被拉回顶部。
   - **失败现象**:切回后视口跳到你进 TUI 前看历史的那个旧位置(甚至顶部)。
