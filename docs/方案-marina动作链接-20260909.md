# 方案:marina: 动作链接 —— 文档内触发 CLI 语义(2026-09-09)

> 状态:已实现(ADR-035)。本文是设计底稿:动机、语法、执行模型、安全论证、
> 取舍记录。使用者视角的语法参考在 `packages/pi-marina-bridge/skills/show-in-marina/`
> 的 SKILL.md 与 MARKDOWN-CAPABILITIES.md(AI 写文档时读那份)。

## 1. 背景与动机

开发者提出(原话摘要):Markdown 链接 `[ABC](#3)` 扩展一种写法 —— 括号里写
`marina:<参数>`,点击后**视为触发 marina skill 里的 CLI 工具**。典型场景:

- **GitLab issue 互链**:agent 拉下一批 issue markdown,自己写脚本预处理一遍
  再 `show` 给用户;issue 正文里对其它 issue 的引用改成 `marina:show` 链接后,
  用户在面板里就能逐个点开关联 issue 的 markdown —— 不经 chat、不经终端。
- **菜单式文档**:agent 给用户一份菜单式 markdown(每项一个 marina: 链接),
  用户按需浏览信息 / 触发查看。

本质:agent 已经能让用户看到这份文档,而 agent 本身就有调 marina CLI 执行任意
指令的权限 —— 文档内嵌动作**不提升权限面**,只是把「下次让 agent 跑」变成
「用户现在点」。

## 2. 语法

```
[标签](<marina:show <path> [--heading <标题>]>)
[标签](<marina:run [--title <标签>] <command...>>)
```

- 只支持 `show` / `run` 两个子命令(取舍见 §5.3)。
- **必须用 `<>` 包裹或把空格写成 `%20`**:CommonMark 裸链接目标不容任何空白,
  `[x](marina:show a.md)` 根本不会解析成链接(实测:整体变纯文本;若尾部恰好
  是引号段则链接成立但 href 被截断到 `marina:show`)。`<>` 内可自然写空格与
  引号。
- 解析规则(`src/shared/marina-link.ts`):percent-decode 一次(URL 传输层
  编码)→ shell 风格分词(单/双引号包裹含空格参数;反斜杠字面,Windows 路径
  不受损;唯一转义是 `\` + 同款引号)→ 位置参数按单空格拼接(show 的路径 /
  run 的命令)。
- `--heading` 可出现在路径前后(与 CLI 示例同形);`--title` 必须写在命令
  **之前**(与 CLI 文档示例同位),之后出现的同名/任意 flag 属于命令本身
  (`marina:run gh issue list --limit 5` 的 `--limit` 归 gh)。
- 参数长度上限 4096 字符。

## 3. 执行模型

```
renderer MdLink 点击(marina: 前缀判定,原始 href 透传,不解析)
  → IPC MARINA_LINK_RUN {sessionId, href, mdPath?}(owner 窗口校验)
    → main dispatchMarinaLink(src/main/marina-link-dispatch.ts)
      → parseMarinaLinkHref(shared 解析器)
      → show: FilePanelService.openFileFromMarkdown(有 mdPath)
             / openFile(无 mdPath,session cwd 基准)
      → run:  CommandPanelService.runCommand(与 HTTP /run 同路径)
```

关键点:

- **「视为触发 CLI」而非「spawn CLI」**:CLI 脚本(marina.ps1 / marina.sh)
  只是 HTTP→网关→服务的客户端;main 进程就在服务侧,直接方法调用语义等价,
  免去每次点击 spawn PowerShell 的 300ms+ 启动延迟与 MARINA_* env 注入
  (面板交互 <300ms 性能底线)。
- **show 的路径基准**:有 mdPath(「已打开」面板的文件)→ 相对 md 文件目录 +
  成员校验(与普通本地链接同防线);无 mdPath(命令面板输出)→ 相对
  session.currentCwd(与 CLI show 一致)。这也是**命令输出里开本地文件的
  第一条通道** —— 权限面与 UI「打开文件」按钮(FILE_PANEL_OPEN)完全相同,
  不引入新边界。
- **run**:与 CLI/HTTP /run 完全同一条 CommandPanelService 路径(去重 upsert、
  刷新策略归用户管)。IPC 通道的 requestingClientId 传点击窗口,输出事件定向。
- 错误(语法错 / 文件不存在 / session 缺失)→ toast,与本地链接失败同 UX。

## 4. 安全模型(为什么无确认弹窗)

与可运行代码块(ADR-023)同一决策链:

1. **授权传递论证**:能让用户看到这份文档的 agent,本身就有在终端里跑
   `./marina show/run` 的完整权限。文档内嵌动作只是把同一权限换个触发方式,
   没有扩大攻击面。
2. **任意来源 md 文件也有一键执行能力是既成事实**:任何用户打开的 .md 早已
   带一键运行代码块(bash/powershell/cmd,ADR-023,同样无确认)。marina: 链接
   的暴露面是它的子集(show 只读打开 + run 走命令面板)。
3. **renderer 永远不解析**:href 原样进 main,解析/路径解析/成员校验全在
   main(owner 窗口校验 + mdPath ∈ 面板列表的成员校验防线与既有通道一致)。
   渲染层只做两件轻量事:前缀判定(分流)+ peek 图标/title 提示。
4. **知情通道**:chip 的 hover title 显示解码后的参数原文 —— 用户点击前能
   看到会执行什么;run 的命令也会出现在命令面板 tab 里,事后可查。

## 5. 取舍记录

### 5.1 直接方法分发 vs spawn CLI 脚本

选**直接方法分发**。spawn 版本的好处是免费获得 CLI 全部子命令与未来演进,
代价是每次点击的 PowerShell 启动延迟(实测量级 300ms+,面板交互底线 300ms
直接击穿)、MARINA_SERVICE/TOKEN/TERMINAL_ID env 装配、CLI 输出无处安放、
以及已安装 skill 版本落后 app 版本时的行为漂移。语义等价的前提下,直接分发
在各方面都占优。

### 5.2 子命令集合只收 show / run

CLI 的其它子命令(workspace / list / close / screenshot / ping)是 **agent 侧
工具** —— 它们的使用者是 agent 自己(探测、清理、截图自测),不是读文档的
用户。文档内点击的语义是「用户按需浏览/触发」,show(看)与 run(跑)覆盖
全部场景。硬塞 close --all 之类进文档只会制造误点面。要扩先改本文 + skill
文档 + 解析器白名单。

### 5.3 渲染样式:动作 chip 而非普通链接

marina: 链接语义是「动作」不是「导航」,渲染成药丸形 chip + 动词图标
(run=▶ / show=📄 / 无法解析=⚠)+ hover 提示参数原文,与普通链接明确区分。
颜色全部 currentColor 派生(color-mix),三套 markdown 主题(marina /
github-light / github-dark / custom)下垫底背景未知,禁止 bg token(样式契约
由 global-css.test.ts 守护,与 .md-code-block 同款)。

顺带(同批用户要求):普通文档链接统一「低调常驻下划线 + hover 加深」,
弥补 marina 主题原先无 hover 反馈、github 主题下划线行为不一致的问题。

### 5.4 位置参数拼接(而非严格单参数校验)

CommonMark 裸目标里空格必须写 %20,解码后必然拆成多个 token —— 严格校验会让
最自然的写法(`marina:show%20my%20report.md`)报「多参数」错。规则定为:
位置参数按单空格拼接(show 的路径 / run 的命令),引号内空格原样保留。代价
是真正的「两个参数」会被当含空格路径(点击后以「文件不存在: <完整名>」
浮错),可接受。
