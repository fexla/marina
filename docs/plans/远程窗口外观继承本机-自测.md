| 4 设置页 | `src/renderer/components/SettingsView.tsx` | `updateSettings()` 远程窗口自动把 appearance 子字段拆出走 local-control 通道(写本机),其余字段仍走 backend-data |

## 3. 我没测的东西(需要开发者人工验证)

> 本功能涉及**真实跨机器远程后端**,我无法在本机单进程环境复现。以下需开发者在
> 两台机器(或 loopback daemon)上人工测。测试步骤见下方 §4 用户测试指南。

1. **远程窗口外观来源**:连远程 daemon 开窗,外观是否显示本机(而非 daemon)的
   theme/字体/语言。
2. **实时同步**:本机本地窗口改主题,远程窗口是否实时跟着变。
3. **设置页写本机**:远程窗口设置页改外观,是否写本机 settings.json(本机其他窗口
   跟着变),且 daemon settings.json 不被改。
4. **非外观设置仍归 daemon**:远程窗口改 shell 默认/behavior,是否写 daemon。
5. **回退兜底**:模拟本机 main 未注册新命令时,远程窗口是否回退 daemon 外观。

## 4. 用户测试指南(给开发者)

### 准备
- 两台机器 A(client)、B(daemon),或单机用 loopback daemon(B 跑 `Marina.exe --headless --daemon`)
- A、B 装不同主题(如 A=rose-pine,B=tokyonight)便于区分
- A 在设置页添加 B 的远程 profile 并连通

### 测试 1:远程窗口外观 = 本机(预计 1 分钟)
1. 在 A 上从侧边栏「Marina 电脑」点 B 开远程窗口
2. **预期**:远程窗口显示 **A 的主题(rose-pine)**、A 的字体/字号/语言
3. **失败现象**:显示 B 的主题(tokyonight)→ 说明 appearance 没走 local-control,查 `window.api.backendProfileId` 判定 / preload 路由

### 测试 2:实时同步(预计 30 秒)
1. 在 A 的一个**本地窗口**里把主题改成第三个主题(如 `nord`)
2. **预期**:刚才那个远程窗口**实时**变成 `nord`(无需重开)
3. **失败现象**:远程窗口不变 → 查 `evt:settings:local-appearance-changed` 广播与 store 订阅

### 测试 3:远程窗口设置页改外观写本机(预计 1 分钟)
1. 在远程窗口的设置页 → 外观,把字号改大
2. **预期**:
   - 远程窗口字号变大 ✓
   - A 的本地窗口字号**也跟着变** ✓(写的是 A 本机)
   - 关掉远程窗口重开,字号仍是刚改的 ✓
3. 去 B 那台机器看 daemon 的 settings.json → **字号应没变**(证明写的是 A 不是 B)
4. **失败现象**:B 的 settings.json 被改了 → 说明 updateSettings 没拆分 appearance,查 SettingsView.tsx:updateSettings 的远程分支

### 测试 4:非外观设置仍归 daemon(预计 30 秒)
1. 在远程窗口设置页改「默认 shell」或某个 behavior 项
2. **预期**:该改动写 **B(daemon)**,A 本地窗口的 shell 不变
3. **失败现象**:A 本地 shell 也变了 → 说明非 appearance 字段误走了 local-control

### 测试 5(可选):回退兜底
- 较难模拟(需协议版本不匹配)。如不做可跳过;握手版本检查通常先拦截。
