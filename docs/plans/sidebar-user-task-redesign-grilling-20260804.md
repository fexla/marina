# 侧栏交互重设计：待裁决问题

> 日期：2026-08-04  
> 目标版本：v0.3.3-preview  
> 状态：等待开发者一次性裁决  
> 触发反馈：远程窗口加文件夹报错、收藏分组无法拖动、侧栏右键菜单与按钮需要从用户任务出发重设计

## 背景与已定结论

Marina 当前把三种概念放进同一个窄侧栏：

1. **当前 backend 的路径**：窗口实际操作的那台电脑上的收藏 / 临时 / 最近路径。普通窗口的 backend 是本机；“Marina 电脑”远程窗口的 backend 是远端 daemon。
2. **SSH 路径**：由当前 backend 再 SSH 到第三台机器，属于路径级远程。
3. **Marina 电脑**：客户端保存的另一台 Marina daemon；点击后必须开新窗口，属于窗口级远程。

这三者技术层级不同，但当前顶部只有“本地 / 远程”两个词。因此在 Windows 连接 FEX 的窗口里：

- “本地”实际指 **FEX 本地路径**，不是眼前 Windows 的本地路径；
- “远程”同时放 FEX 的 SSH 路径和 Windows 客户端保存的“Marina 电脑”；
- 同一个 `+` 在不同窗口/分段可能打开 Windows 文件夹选择器、远端路径流程、SSH 服务器菜单或错误流程，用户无法靠图标预测结果。

本轮已完成但尚未发布的机械修复：

- 远程 backend 的原生文件夹选择器错误已定位：`BOOKMARK_PICK_FOLDER` 经 WS 到 daemon 后没有 Electron `webContents`，导致 `getOwnerBrowserWindow` TypeError。
- 已增加 `RemoteDialogUnavailable` 防线，并实现**点击式 backend 目录选择器**：Home / 根目录 / 上一级 / 子目录 / 选择当前文件夹，全程无路径输入，符合《软件定义书》原则 2。
- 收藏分组已增加真实 drag handle 和组排序；同时修复 local / SSH 混合收藏时拖动只提交可见子集、被 main 拒绝的问题。
- 自动测试通过；真实 Electron 指针拖动已验证 DOM 与 main 持久顺序一致。

以下是“菜单与按钮重设计”需要开发者裁决的产品问题。每题都给出我的推荐；可在文末按 `1A 2B ...` 一次性回复。

## 问题 1：顶部到底按“路径来源”还是按“远程功能”分区？

**依赖：根问题；问题 2、3、5、6 依赖本题。**

### 背景事实

当前 segmented control 的“本地 / 远程”按 `PathNode.kind` 过滤：`local` 与 `ssh`。但“Marina 电脑”不是路径，而是窗口级连接，却也被塞在“远程”段里。远程 backend 窗口中，“本地”一词还会错误暗示客户端 Windows。

代码证据：

- `src/renderer/components/Sidebar.tsx`：`effectiveSegment` 按 `kind==='local' / 'ssh'` 过滤。
- `docs/方案-远程UI统一-20260803.md`：SSH 是路径级，Marina 电脑是窗口级，架构上不能抹平。

### 待裁决

- **A（推荐）**：顶部路径切换改名为 **“当前电脑 / SSH”**；远程 backend 窗口把“当前电脑”动态显示为 `FEX`（或保存的电脑名）。“Marina 电脑”独立为一个小节，不再伪装成路径来源。
- **B**：保留“本地 / 远程”，只在远程窗口加说明文字解释“本地 = FEX”。
- **C**：取消 segmented control，把本机路径、SSH 路径、Marina 电脑都常驻为三个独立 section。

### 我的推荐

选 **A**。用户首先要回答“我正在操作哪台电脑”，其次才是“这个路径是否又经过 SSH”。动态电脑名比“本地”准确；把窗口级电脑列表与路径级 SSH 分开，也让后续按钮语义可预测。

## 问题 2：两个 `+` 在不同上下文中应该完成什么用户任务？

**依赖问题 1。**

### 背景事实

当前：

- 收藏 `+` 在本机路径段是“选择文件夹加入收藏”；在 SSH 段是“选服务器后手输路径”；在远程 backend 路径段曾错误调用 native dialog。
- 临时 `+` 在 SSH 段仍创建本地 session，创建后马上被当前 SSH 过滤隐藏。
- 《软件定义书》明确禁止路径文本框；现有 SSH 手输 `~/project` 与产品哲学冲突。

### 待裁决

- **A（推荐）**：
  - “当前电脑”段：收藏 `+` = 点击式文件夹选择器；临时 `+` = 同一选择器后立即开终端。
  - “SSH”段：不手输路径。收藏 `+` 改为 **“连接 SSH…”**，选择服务器后从 home 启动 session；用户通过 shell 到达目录后，从临时/最近路径点“加入收藏”。临时 `+` 同样是“连接 SSH…”。
- **B**：给 SSH 增加 SFTP 式目录浏览器，再保留“直接选择 SSH 文件夹”。
- **C**：把“SSH 手输路径”作为产品原则 2 的正式例外写入文档。

### 我的推荐

选 **A**。B 会把 Marina 扩成远程文件管理器，违反当前“不做 SFTP / remote Explorer”的边界；C 会破坏最核心的“不让用户输入路径”哲学。A 用已有 session/cwd 状态自然发现路径，技术面也最小。

## 问题 3：操作系统文件拖入在哪些上下文可用？

**依赖问题 1、2。**

### 背景事实

当前整个侧栏在任何分段/窗口都显示“松开以加入收藏”，并把客户端 `File.path` 发给当前 backend：

- SSH 段：创建本地收藏后被隐藏；
- 远程 backend：把 Windows 路径发给 Linux daemon，通常报不存在；若恰好同名，甚至可能收藏错误目录。

### 待裁决

- **A（推荐）**：只在“客户端本机 backend + 当前电脑段”接受 OS 文件夹拖入；其它上下文不显示可放置反馈，并在误拖时给解释 toast。
- **B**：远程 backend 也接受拖入，把客户端目录上传/映射到 daemon。
- **C**：所有上下文都禁用 OS 拖入，只保留选择器。

### 我的推荐

选 **A**。B 是文件传输新产品；C 会丢掉本地高价值快捷操作。A 的机器归属最清楚。

## 问题 4：分类与分组的按钮、右键菜单如何去重？

**可独立裁决。**

### 背景事实

当前：

- 收藏 / 临时 / 最近三个分类右键都显示“新建分组”，但临时、最近按状态机不能分组；动作实际偷偷创建收藏分组。
- 分组头 hover 同时有铅笔、垃圾桶；右键又重复新建、重命名、删除。
- 删除分组不会删路径，只把路径移回未分组，但“删除”文案容易让人害怕。
- 本轮已经加了明确的拖动 grip。

### 待裁决

- **A（推荐）**：
  - 收藏标题保留 `+`，再加显式 `⋯`；`⋯` 只有“新建分组”。右键与 `⋯` 打开同一菜单。
  - 临时 / 最近取消右键菜单。
  - 分组头只显示 grip、折叠箭头、名称、`⋯`；去掉 hover 铅笔/垃圾桶。
  - 分组 `⋯`：重命名、**解散分组（保留路径）**。不再放“新建分组”。
- **B**：保留 hover 快捷按钮，右键只删除重复项。
- **C**：全部动作只放右键，不显示 `⋯`。

### 我的推荐

选 **A**。右键可以保留给熟练用户，但关键入口不能依赖隐藏手势；每个层级只承担自己的动作，名称也准确表达数据不会被删。

## 问题 5：路径右键菜单按什么任务分组、哪些机器相关动作应隐藏？

**依赖问题 1。**

### 背景事实

当前菜单按实现不断追加：复制路径、Explorer、安装 Skill、重命名、移除收藏、每个模板一条菜单项、加入收藏、从最近移除。问题包括：

- 远程 backend 路径的“在 Explorer 中显示”会在 daemon 桌面打开，客户端用户看不到；SSH 路径已隐藏该项。
- 默认模板列表平铺，模板多时菜单很长；后端支持 `templateId:null`，但 UI 没有“跟随全局默认”。
- “移除收藏”在无 session 时还额外从最近移除，与名称和状态机预期不一致。

### 待裁决

- **A（推荐）**：按用户任务分区：
  1. **打开/定位**：仅客户端本机路径显示“在文件管理器中显示”；远程 backend / SSH 不显示。
  2. **复制**：复制路径。
  3. **组织**（仅收藏）：重命名、移动到分组（拖拽之外的可发现兜底）、移除收藏。
  4. **启动方式**（仅收藏）：子菜单“默认模板”，第一项“跟随全局默认”，再列模板。
  5. **项目工具**：安装 Marina Skill（当前 backend 本地路径可用，文案显示目标电脑）。
  6. 最近路径保留“从最近移除”；临时/最近保留“加入收藏”。
  7. “移除收藏”只执行 `BOOKMARK_REMOVE`，不再暗中删最近记录。
- **B**：仅修远程 Explorer 和默认模板清除，其它布局不变。
- **C**：菜单极简，只留复制、重命名、加入/移除收藏，其它功能移设置页。

### 我的推荐

选 **A**。功能没有减少，但用户看到的是任务，而不是 IPC/数据结构；机器相关功能只在用户看得见结果的地方出现。

## 问题 6：Session 右键菜单是否折叠“诊断信息”？

**依赖问题 1。**

### 背景事实

当前每个 session 都平铺 8 项：重命名、复制初始路径、复制 cwd、复制 PID、Explorer、新窗口、简易窗口、关闭。远程 backend / SSH session 的 Explorer 同样可能在错误电脑或无人桌面打开；三个复制项占据大量高度。

### 待裁决

- **A（推荐）**：
  - 主任务：重命名、在新窗口打开、在简易窗口打开、关闭。
  - 子菜单“复制信息”：当前目录、初始目录、PID。
  - “在文件管理器中显示”只对客户端本机的 local session 出现。
  - 被其它窗口持有时，禁用项带明确原因 tooltip，不只是灰色。
- **B**：保持平铺，只按 backend/location 隐藏 Explorer。
- **C**：删掉复制 PID 与初始路径，仅留复制 cwd。

### 我的推荐

选 **A**。正常工作流与诊断信息分层；功能不丢，菜单高度显著下降，也减少“哪个路径才是我要的”困惑。

## 问题 7：危险/破坏性动作的确认策略是什么？

**依赖问题 4、5、6。**

### 背景事实

- “解散分组”不删路径，可撤销成本低（重新分组即可）。
- “移除收藏”不删磁盘内容，只改变组织状态。
- “从最近移除”会删除历史记录但不删路径。
- “关闭 session”会终止 PTY；项目现有哲学反对给普通关窗增加确认，但 session 关闭本身是明确动作。

### 待裁决

- **A（推荐）**：前三者不弹确认，用准确文案 + success toast；关闭 session 保持现有行为，不新增确认。仅真正删除文件/数据时才确认。
- **B**：解散分组、从最近移除、关闭 session 都确认。
- **C**：危险菜单项二次点击确认，不弹 modal。

### 我的推荐

选 **A**。符合“用户决策最少化”和“窗口/会话低成本”哲学；通过文案避免误解，而不是用弹窗弥补坏命名。

## 问题 8：计数与折叠文案是否在本轮一起纠正？

**可独立裁决。**

### 背景事实

- 分类 header 的 tooltip 写“展开分组 / 折叠分组”，实际折叠的是收藏/临时/最近分类。
- 路径右侧 session 数量包含 exited session，但代码变量叫 `activeCount`，文档又称“活跃终端数量”。exited session 可长期保留，因此数字可能看起来虚高。

### 待裁决

- **A（推荐）**：本轮一起修：tooltip 改“展开/折叠收藏（或临时/最近）”；路径 badge 只显示未 exited session 数量，若全部 exited 则隐藏 badge（exited 仍在展开列表中可见）。
- **B**：badge 显示 `活跃/总数`（例如 `2/4`）。
- **C**：只修 tooltip，计数保持总 session 数并更新文档。

### 我的推荐

选 **A**。侧栏 badge 应回答“现在有几个终端活着”，而不是“历史上留下几个 session 行”；退出项仍在展开列表，不会丢信息。
