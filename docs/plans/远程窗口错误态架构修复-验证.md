## 一、我做了什么(架构修复总结)

### 根因(详见设计文档)
所有窗口都是 `frame: false`(自绘标题栏)。renderer 里"可见状态必须渲染 `<WindowChrome>` 才有标题栏"这条约束**只靠每条分支自觉**;本机外观获取又死耦合在连接成功路径。结果:`mismatch` 分支漏画标题栏(Bug 1),错误态拿不到本机主题(Bug 2),且修一条复发一条。

### 改动(2 个文件)

**新增 `src/renderer/components/LocalAppearanceProvider.tsx`**
- App 最顶层挂载(handshake 之前),拉 local-control 命令 `SETTINGS_GET_APPEARANCE` + 订阅 `SETTINGS_LOCAL_APPEARANCE_CHANGED`。
- 关键:preload 对 local-control 命令 **bypass `ensureTransport`**(`src/preload/index.ts` invoke()),所以**远程连不上时也走客户端本地 ipcRenderer 立即返回** → 错误态也能拿本机主题。
- 提供 `useLocalAppearance()` hook。

**改造 `src/renderer/App.tsx`**
- 新增 `<FramelessShell>`:frame:false 窗口的基础外壳,**结构上保证**可见状态必有标题栏(WindowChrome)+ 本机主题。把"必有标题栏"从口头约定变成结构强制 → 防复发。
- 新增 4 条分支的卡片组件:`PendingCard` / `ProtocolMismatchCard` / `LocalStartupErrorCard`(远程错误仍用改造后的 `RemoteConnectionErrorScreen`)。
- **4 条握手/错误分支全部改走 `<FramelessShell>`**:pending、mismatch、handshake error(远程+本地)、sync.error(远程+本地)、!sync.ready。
- `RemoteConnectionErrorScreen` 剥离外壳职责(不再自己渲染 WindowChrome/data-theme/Provider),只留错误卡片。
- **删除 `FullPagePlaceholder`** —— 它在 frame:false 项目里是"无标题栏"陷阱(诱使复发),删掉让该状态在代码里不可表达。
- 提取 `detectRemoteWindow()`,消除原先 3 处重复的 `?backend=` 判定。
- 加 `window.api` guard:preload 没加载时降级渲染静态卡片,避免白屏。

### 没动的(刻意)
- `useIpcSync` 那段本机外观覆盖(store.tsx):正常路径已正确,不改(避免时序坑 + 不动已通过代码)。

## 三、用户测试指南

### 准备
```powershell
cd D:\data\projects\agent\marina
```

---

### 场景 1:本地窗口零回归(预计 30 秒,必测)

1. `npm run dev` 启动。
2. **预期**:Marina 窗口正常出现,标题栏在(右上角最小化/最大化/关闭按钮),主题是你设的主题,终端能输入。
3. 切到设置页改主题 → 窗口立即换主题。
4. **失败现象**:窗口白屏 / 无标题栏 / 主题不对 → 把 `~\AppData\Roaming\Marina\logs\main.log` 最后 50 行发我。

> 这是回归基线:确认我没把正常路径搞坏。

---

### 场景 2:协议版本不匹配 — Bug 1 现场(预计 2 分钟,必测)

**复现方法**:临时让 main 返回的协议版本 ≠ renderer 期望值。

把 `src/main/ipc.ts` 第 534 行:
```typescript
      protocolVersion: PROTOCOL_VERSION,
```
临时改成:
```typescript
      protocolVersion: PROTOCOL_VERSION + 1,
```

然后:
1. `npm run dev` 重启。
2. **预期(Bug 1 修复后)**:
   - 窗口出现,**标题栏在**(能最小化/最大化/关闭)。
   - 内容是"协议版本不匹配"卡片,显示 `主进程协议版本 v5,渲染端 v4`。
   - 有"关闭窗口"按钮。
   - **主题是你设的本机主题**(不是默认 rose-pine,除非你本来就设的 rose-pine)。
3. 点最小化/最大化/关闭,确认标题栏按钮真的工作。
4. **测完务必改回** `protocolVersion: PROTOCOL_VERSION,`。

**远程版本不匹配**(你之前遇到的真实场景):如果你有两台机器跑不同版本 Marina,远程连接时复现 —— 预期同上(标题栏在 + 本机主题 + 卡片说明"本机与对方协议不一致")。

---

### 场景 3:远程连接失败 — Bug 2 现场(预计 2 分钟,必测)

1. 先在本机设置页把主题改成**一个非默认主题**(比如 tokyo-night / catppuccin 等,只要不是 rose-pine)。
2. 设置 → 远程 → 新增一台"Marina 电脑",**故意填错**:IP 填一个不通的地址(如 `192.168.99.99`),端口 32780,密码随便。
3. 托盘 → "打开远程电脑" → 选刚才那个错 profile → 开新窗口。
4. **预期(Bug 2 修复后)**:
   - 新窗口**标题栏在**。
   - **主题是你刚才设的那个非默认主题**(不是 rose-pine)← 这是 Bug 2 的核心验证点。
   - 内容是远程连接错误卡片:针对性诊断(如"无法连接到对方电脑")+ 排查清单 + 可复制的详细错误 + 重试/关窗按钮。
5. 在**另一个窗口**把主题再切一个 → 回到错误窗口,确认错误页主题**跟着变**(实时同步)。
6. 点"重试连接" → 重新加载;点"关闭窗口" → 关掉。

---

### 场景 4:握手中状态(预计 30 秒,选测)

1. 场景 3 的错 profile 连接过程中,或慢网络下。
2. **预期**:握手期间窗口**已有标题栏**(不再是"先无标题栏、连上后突然出现"的闪烁),内容是"正在连接…"。

---

### 场景 5:加载状态(预计 30 秒,选测)

正常情况下 snapshot 加载很快看不到。若想确认:`!sync.ready` 分支现在也走 FramelessShell(标题栏在 + "加载状态…"卡片)。这个分支极短,选测即可。
