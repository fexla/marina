# 方案:命令面板整合进「已打开」面板(ADR-037)

日期:2026-09-09
状态:已实施(commit efee9fd / f402b64 / 3a2e47c)
关联:ADR-016(Panel Registry)、ADR-021(后台任务 demand)、ADR-027/028(命令面板)、
ADR-036(Markdown 能力全源复用)

## 0. 背景与动机

开发者三条反馈(2026-09-09):

1. `marina run` 触发时,如果指令 tab 已存在,不会跳转 —— 与 `marina show`
   (openFile"已存在则等价 show",总是跳)行为不一致。
2. **"命令面板整合进'已打开'面板吧,太相似了。"** —— 两面板同构:
   program-push + 多 tab + markdown 渲染;ADR-036 后连 Markdown 能力都全源
   复用了,独立 dock 面板只剩"多一个 tab 切换"的成本。
3. 命令渲染的页面应与 markdown 一样记忆浏览位置。

三条同批处理:① 是 main 服务层语义修正;② 是 UI 归属变更;③ 在 ② 落地后
自然变成"统一 tab 列表的滚动记忆"问题。

## 1. 决策:UI 归属变更,数据层不动

**关键取舍**:只合并 renderer 的面板宿主,**不合并 main 服务**。

- `CommandPanelService`、`COMMAND_PANEL_*` IPC 通道、`evt:command-panel:updated`
  事件、调度器接线全部原样保留。remote daemon / HTTP 网关 / marina:run 链接
  分发路径零改动。
- 持久化不变:file-panel.json 不吞命令列表(命令仍是内存态,`restoreSnapshot/
  exportSnapshot` 维持现状待未来接线)。
- 理由:合并数据层需要迁移两个 schema + 双事件流合一,回归面大;而用户痛点
  纯粹是"两个 dock tab"。UI 合并后数据层的分离完全不可见。

## 2. 结构

### 2.1 dock 4 → 3

- `RegisteredPanelId = 'file-tree' | 'git' | 'file-panel'`(去掉 `'command'`)。
- `createSessionLayoutTree(gitAvailable)` 不再生成 command leaf,
  `commandAvailable` 参数删除(它本来就是恒 true 的预留)。
- 命令侧 UI 三件套(原 CommandPanel.tsx 重构):
  - `CommandTabStrip` —— 统一 tab 列表里的命令 tab 段(状态点 + 标题 + ×)
  - `CommandToolbar` —— 前后台范围 / 刷新间隔 / 立即刷新 / SSH sudo
  - `CommandPane` —— 输出区(命令 → 共享 MarkdownDocument)+ sudo 密码条
- FilePanel 组合渲染:文件 tab 在前、命令 tab 在后,中间细分隔线;tab 列表
  搜索过滤同时作用于两侧(文件按名、命令按标题/命令文本)。dock 徽章计两侧
  tab 总数。

### 2.2 面板内视图状态(store.openPanelViews)

面板内"正在看哪一侧"是一个新的 view state,`'file' | 'command'`:

- `openFile` 的 requestActivation → `activePanels='file-panel'` +
  `openPanelViews='file'`;
- `runCommand` 的 requestActivation → `activePanels='file-panel'` +
  `openPanelViews='command'`(main 端 activeKey 已指向该指令);
- 用户点 tab → `view/set-open-panel-view`(幂等,同值返回原 state)。

`resolveOpenPanelView(stored, fileCount, commandCount)` 兜底:无记录默认文件侧;
记录的一侧被清空时回退另一侧 —— 否则关掉最后一个文件会停在永远空着的文件侧。
FilePanel(渲染/滚动/demand)与 LayoutHost(SearchBar 导航器 gate)共用这一份
判定,防两处漂移(open-panel-view.ts + 单测钉死)。

### 2.3 runCommand 激活语义(反馈 ①)

与 openFile 的"已存在则等价 show"对齐:

- 无论 isNew,`runCommand` 都把 activeKey 切到该指令并请求激活;
- 激活事件**在 spawn 前发出**:长命令先跳面板看到 running 占位/上一轮结果,
  而不是跑完才跳(原实现 post-await 才 emit,requestActivation=isNew);
- 完成态 emit 保持 requestActivation=false,被 supersede 的旧调用不发激活;
- 面板 rerun 按钮也走 runCommand,但那时该 tab 本就 active,激活是幂等 no-op;
- 后台调度器自动刷新走 spawnRun 直跑(不经 runCommand),不抢激活。

### 2.4 调度 demand 上报(ADR-021)

原:CommandPanel 组件挂载 = HOT,卸载 = NONE(LayoutHost 卸载非 active 面板,
挂载即可见)。整合后该假设失效(命令 UI 常驻 FilePanel 内),改为 FilePanel 上报:

```
hot  ⇔  FilePanel 挂载(active dock 面板是已打开)
      ∧ dock 未折叠
      ∧ 面板内视图在命令侧
none ⇔  其他(切文件侧 / 折叠 dock / 切走 dock / 卸载)
```

main 端 `applySchedulerDemand` 仍结合 activeKey(哪条指令 tab 在看)做 per-task
映射,foreground→NONE 真停、background→WARM 保温语义不变。顺带修复原实现
"dock 折叠时命令面板仍报 HOT"的 wart。

### 2.5 命令输出滚动记忆(反馈 ③)

复用文件侧 `useFileViewerScroll`(identity = sessionId + path + kind):

- 命令条目 path = `command:<key>`、kind = `'command'`(伪 kind;真实文件路径
  不会以 `command:` 开头 —— Windows 盘符 / POSIX 绝对路径,无冲突,与
  MarkdownDocument documentIdentity 同约定)。
- `restoreVersion` 恒为 entry.key(**不用 lastRunAt**):自动刷新/重跑高频替换
  output,version 若跟着变,每次刷新都会把视口拉回旧保存点,长输出没法读;
  只有 identity 切换(换命令 tab / 切走再切回触发 remount)才恢复。
- `ready = entry.output.length > 0`:尚无完成结果(等待占位)时走 !ready 清零。
- store 防线:`view/file-viewer-scroll` 对 `command:` 路径按 commandPanels
  当前列表校验(late flush 不复活);`command-panel/updated` 裁掉已关命令的
  条目;`file-panel/updated` 的文件裁剪不误删命令条目(同 bucket 共存)。
- workspace 快照写盘过滤 `command:` 条目:命令列表本身不跨重启,落盘只会留
  永远无人消费的孤儿条目(restore 端本来也会因 openedFiles 不含而跳过,双保险)。

### 2.6 CSS

- `.command-panel-content` / `.command-panel-tabs` / `.command-panel-body` 删除:
  宿主统一为 `.file-panel-content` / `.file-panel-tabs` / `.file-panel-body`
  (user-select: text 恢复契约由 `.file-panel-body` 继续承担,global-css.test
  同步);`.command-tab*` / `.command-panel-toolbar` 等内层类原样保留。
- `.file-panel-body:has(.markdown-body) { padding: 0 }` 契约自动覆盖命令输出。
- 新增 `.file-panel-tab-divider`。
- `data-viewer-kind='command'`(data-viewer-path=commandKey)用于排障定位;
  默认 overflow 分支与 markdown 一致。

## 3. 边界情况核对

- **SSH session**:命令面板对 SSH 的可用性(远程 sudo、ssh exec)不变;
  `isSsh` 判定移到 FilePanel 传入三件套。
- **SearchBar 导航器**(文件内查找跳转):`activePanelId==='file-panel'` 时按
  `openPanelView` 分流 —— 文件侧要有打开文件,命令侧要有输出。
- **LayoutHost activePanels 校验**:旧 store 里残留的 `'command'` 值不在
  panelIds 里 → 自动回退 defaultPanelId(既有兜底,无需迁移代码)。
- **面板切换性能**(AGENTS.md <16ms 约束):文件↔命令切换不经过 LayoutHost 的
  ActivePanel 重挂,只重渲染 FilePanel 内部;数据都在 store 快照,无首拉。
- **smoke-interactive**:只钉 `已打开`/`文件` tab 标题,不碰 command 面板。
