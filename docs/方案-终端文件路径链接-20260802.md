## 0. 背景:这个 feature 要解决什么(自包含,供任意 session 阅读)

### 一个具体场景

你在 Marina 终端里跑测试,屏幕上出现:

```
FAIL src/main/session-manager.test.ts
  ● SessionManager > createSession > 应该创建 PTY

    at src/main/session-manager.ts:1061:15
```

那行 `src/main/session-manager.ts:1061` 是一个**相对路径**(相对当前终端的
工作目录)。现在它只是屏幕上的死字。要看这个文件,你得切到文件管理器、手动
导航、再打开——而文件已经在 Marina 的"操作面"(终端)旁边了。

**Feature F 要做的:让这种路径能"打开"——点一下,右边「已打开」面板里只读
显示该文件内容。** 核心价值场景:AI agent(或编译器/测试框架)在终端吐报错、
吐文件引用,你一眼就能点开看。

### 它和已有功能的两条界线(避免混淆)

- **vs Feature B(T02,已实现)**:B 是 **Markdown 查看器内部**的 `[text](path)`
  链接 → 面板。F 是 **终端输出**的裸文本路径 → 面板。不同 surface(界面位置),
  但**复用同一个打开通道**(`cmd:file-panel:open`)。
- **vs `marina show`**:那是**程序主动**推送文件进面板(程序说"请打开这个");
  F 是 Marina **被动检测**终端文本里的路径(用户点了文本才触发)。

### 已有基础设施(实现路径已通,T15 只需写前端检测 + 复用)

打开一个相对路径并切到面板,已经有完整链路,**无需后端改动**:

| 环节 | 位置 | 作用 |
|---|---|---|
| IPC 通道 | `src/shared/protocol.ts:227` `FILE_PANEL_OPEN: 'cmd:file-panel:open'` | renderer → main |
| payload 允许相对路径 | `src/shared/protocol.ts:1503` 注释「path 可相对 session.currentCwd」 | main 侧自动按 cwd 解析 |
| main handler | `src/main/ipc.ts:1867` `filePanelService.openFile(sessionId, path)` | 读文件 + 进面板 |
| 自动切面板 | `src/renderer/store.tsx:469` `requestActivation` 时把 activePanel 设为 `file-panel` | 打开成功即切 |

即:**前端解析出 path 字符串后,一行 `cmd:file-panel:open` 就完成"解析相对 cwd +
打开 + 切面板"全流程。** T15 的工作量集中在"怎么从终端文本里把路径认出来 +
怎么让用户触发"。

## 1. 触发方式 = **C:自动变链接 + 右键菜单兜底**(已定)

- **自动链接**(A 部分):鼠标移到终端里的路径上,它变蓝带下划线(像网页链接),
  点一下就打开。体验好,但要扫描终端每行文本、有误识别风险。
- **右键菜单**(B 部分):选中一段文字或鼠标停在路径上,右键 → 菜单里点
  「在面板打开此路径」。零误识别(用户主动触发),且终端**已有完整右键菜单框架**
  (`src/renderer/components/TerminalView.tsx` 的 `ContextMenu`,现有 4 项:
  复制/粘贴/清屏/搜索),加第 5 项是纯增量。
- **决策**:两个都做。自动链接负责"所见即所点"的主体验,右键菜单负责零误识别的
  兜底(尤其对自动正则漏掉的形态)。

> ③=C 直接约束下面的**决策 1**(检测范围):A 部分会扫描每一行,正则必须严;
> B 部分是用户主动选中,机制不同(见决策 1)。

### 决策 1:什么样的终端文本算"文件路径"?(误识别主战场)

**结论:A 自动链接用 STRICT(要斜杠);B 右键菜单不做正则预判、选中即试。
不引入 WIDE(认裸文件名)规则。**

#### 两种机制的本质区别(为什么 B 不需要 WIDE)

- **A 自动链接 = 机器扫描每一行**,需要一个正则决定哪些词变蓝。误识别代价高
  (满屏假链接、点错伤信任)→ 必须**严**。
- **B 右键菜单 = 用户主动选了一个词**,用户已表达"我想打开这个"的意图,机器
  不用猜"这像不像路径"→ **不需要正则**,把选中文本直接传给 `cmd:file-panel:open`
  让 main 试解析即可。失败走决策 3 的 toast。

所以 B 不是 WIDE。WIDE 的危害在于"自动扫描每行误中 `.property`";B 是用户指着
一个词,不存在扫描误识别问题。整个 feature **只有一套正则(STRICT),只挂在 A 上**。

#### STRICT 规则

要求**至少一个斜杠 + 点扩展名结尾**,可选 `:行:列`。扩展名用宽松形态
(`.\w{1,8}`,不写死白名单,省维护)。

示意正则(T15 实现时需打磨:处理括号包围 `(src/x.ts)`、双扩展名 `.test.ts`、
URL 优先级):

```
/(?<![\w.([{"'])(?=[\S]*\/)[\w./\\@\u4e00-\u9fff-]+\.\w{1,8}(?::\d+(?::\d+)?)?/g
```

- **URL linkifier 优先**:`http://...` 归现有 WebLinksAddon(T13);文件正则只在
  非 URL 文本上跑,避免吞 URL。
- **裸文件名**(`README.md`、`foo.ts`)A 自动**不**变蓝(无斜杠);但 B 右键选中
  仍能打开(选中即试,main 按 currentCwd 解析裸名为 `cwd/foo.ts`)。

#### 为什么不认裸文件名(数据实证)

跑了 22 条真实终端样本(编译器报错 / npm test / git log / 代码输出 / URL / 中文路径)
对比 STRICT vs WIDE,详见 [原型对比文档](../prototypes/T14-裸文件名规则对比.md):

| 指标 | STRICT(要斜杠) | WIDE(认裸文件名) |
|---|---|---|
| 正确命中真路径 | 8 / 12 | 9 / 12 |
| 漏识别 | 4 | 3 |
| **误识别(非路径)** | **3**(全是 URL,被 URL 优先规则挡掉 → 归 0) | **13**(**10 个是代码属性访问**) |

WIDE 多赚 3 个裸文件名真路径,代价是多 10 个误识别——几乎全是 `arr.length`、
`obj.toString`、`data.map`、`res.json` 这类属性访问。终端跑 `node`/`tsc`/REPL 时
这种输出**满屏都是**,会变成满屏假链接。**误识别伤信任,漏识别只是多一步右键**,
代价不对称。数据验证了 STRICT。

### 决策 2:相对什么解析路径? = `session.currentCwd`,无降级(已定)

**结论:直接用 `session.currentCwd`,不写降级逻辑。**

事实(`src/main/session-manager.ts:1061`):`currentCwd` 在 **spawn 时就初始化**
成启动 cwd(本地)或 pathId 路径(SSH)。OSC 1337 / NtQuery 轮询只是**更新**它,
不是唯一来源。所以**它永远不为空**,总有 spawn cwd 兜底。无需为"不可知"这种
不存在的情况写代码。

### 决策 3:路径不存在时怎么反馈? = toast + 不预探盘(已定)

**结论:不预探盘(hover 时不发 IPC);点了失败 → toast「文件不存在: <path>」,
不弹 modal。**

推理:
1. 自动链接若 **hover 时**就 IPC 探盘"这文件在不在",每个命中链接都发一次——
   终端输出量大时是 N 次 IPC,性能不可接受。
2. 所以自动链接 hover 态不变(看起来都可点);点了之后 main 返回失败再反馈。
3. 反馈用 toast(和现有 `cmd:file-panel:open` 失败语义对齐,FilePanel 已有 error
   toast 先例),控制台同时 warn 便于调试。**不弹 modal**(违反"窗口零成本",
   文件打不开不致命)。

---

### 决策 4:行号 `:42` 要不要跳转/高亮? = **做跳转,不做高亮**(已定)

**结论:点开 `src/x.ts:42` 后,面板滚动到第 42 行;不做行高亮(不画背景标记)。**

链接文本含 `:行:列`,IPC payload 带上 `line` 字段;点开后 TextViewer 滚动到该行
并进入可视区,但不做"整行背景色高亮"。

> ⚠️ **这给 TextViewer 新增了能力需求,算进 F 范围**:
> 当前 `src/renderer/components/file-panel/TextViewer.tsx` 只**渲染文件前 N 行**,
> **完全没有"滚动到第 X 行"的能力**。T15 需新增:
> - TextViewer 支持全量(或按需)渲染 + 滚动;
> - `scrollToLine(line)` 入口,打开时若 payload 带 `line` 则滚动定位;
> - 行高亮**不做**(本 ticket 明确排除,留作后续可选)。

行号正则一起匹配进链接(整个 `src/x.ts:42:8` 是一个链接,不会出现"path 能点但
`:42` 点不到"的割裂感)。列号 `:8` 解析出来但当前不利用(行定位足够)。

---

### 决策 5:远程 SSH session 怎么办? = `SshUnsupported` 占位(已定)

**结论:SSH session 直接 `SshUnsupported` 占位,和 gallery(ADR-026)、Feature B 一致。**

事实(`src/main/session-manager.ts:1061`):SSH 下 `currentCwd = pathRef.path`
(远程路径字符串)。本地 FilePanel 用本地 fs 读不到远程文件 → 打开必失败。
模式统一:远程本地图不可达 → 失败占位提示。

- 自动链接:SSH session 下不注册文件路径 link provider(只留 URL)。
- 右键菜单:SSH session 下不显示「在面板打开此路径」项(或置灰提示远程不支持)。

## 4. T15 实现指引

- **A 自动链接**:自定义 xterm link provider(`term.registerLinkProvider`),
  STRICT 正则命中 → hover 变蓝 → 点击发 `cmd:file-panel:open`(payload 带 `line`
  若有)。URL linkifier(T13 的 WebLinksAddon)保持优先,文件正则只跑非 URL。
- **B 右键菜单**:终端右键菜单(`TerminalView.tsx` 现有 `ContextMenu`)加第 5 项
  「在面板打开此路径」;取选中文本(或光标下词),不做正则预判,直接发
  `cmd:file-panel:open` 让 main 按 currentCwd 解析。
- **TextViewer 行定位**:新增全量/按需渲染 + `scrollToLine(line)`,payload 带
  `line` 时打开后滚动定位;**不实现行高亮**。
- **失败反馈**:`cmd:file-panel:open` 失败 → toast「文件不存在: <path>」+ console warn。
- **SSH**:session 为 SSH 时不注册 A 的 link provider、B 菜单项不显示。
- **复用**:全程复用现有 `cmd:file-panel:open`(相对 cwd 解析 + 打开 + 切面板),
  **无需后端改动**(决策 4 的 TextViewer 行定位除外,那是前端能力)。
